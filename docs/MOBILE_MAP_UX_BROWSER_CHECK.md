# 모바일 UI 브라우저 검수 기록

확인일: 2026-10-15. main `4cf9a8b` 위 모바일 UI 1~5단계 미커밋 작업 기준.
로컬 API `127.0.0.1:8080`, Vite `127.0.0.1:5173`, Chrome을 사용했다.
Kakao JavaScript 허용 도메인과 맞는 `http://localhost:5173/`에서 실제 지도 타일·마커를
확인했다. CSS viewport와 DPR은 브라우저 DOM 값으로 측정했다.

## 최종 브라우저 확인

### 기본 화면과 반응형

- `/`, LIVE, DPR 약 1에서 `360×740`, `390×844`, `430×932`를 확인했다. 세 화면 모두
  문서 너비와 viewport 너비가 같아 가로 넘침이 없었고 Kakao 지도 타일이 로드됐다.
- 모바일 헤더는 약 65px였다. 360×740에서 헤더와 검색 입구는 약 125px 안에 들어왔고,
  상시 범례·검색 모드 행·선택 전 빈 시설 카드가 없었다.
- `전체 시설`, 44px 확대·축소, `지도 설정`이 Kakao 축척·로고와 겹치지 않았다.
  `700×360`에서는 세 조작 묶음이 높이 48px 한 줄로 바뀌고 가로·세로 넘침이 없었다.
- 계획에 지정된 `740×360`은 700px 모바일 경계보다 넓어 기존 PC 화면으로 전환됐다.
  가로 넘침은 없고 기존 데스크톱 최소 높이 540px에 따라 세로 스크롤이 생겼다.
- `701×700`, `1440×900`에서 기존 PC 헤더·검색 모드·필터·기상·상시 범례·시설 안내
  카드와 Kakao SDK 확대 막대가 유지됐다. 모바일 전용 헤더와 하단 버튼은 나타나지 않았다.
- `390×844`에서 브라우저 페이지 배율 125%를 적용해도 문서 가로 넘침이 없고 하단 버튼이
  조작 범위 안에 남았다. 이 확인은 OS의 접근성 글자 확대와 동일한 시험은 아니다.

### 상태·패널·검색

- LIVE 기본 화면에서 헤더의 `KMA 정상`과 기준 시각, 자료 상태 패널, 더보기의
  중앙관제·새로고침·기상청·모의훈련 전환을 확인했다.
- 실제 응답 복사본의 `status.health`만 브라우저 시작 전에 바꾼 검수용 모의 응답으로
  STALE과 ERROR를 확인했다. STALE은 `KMA 수신 지연`과 `마지막 정상 자료 표시 중`,
  ERROR는 `KMA 조회 불가`와 `시설 위치만 확인 가능`을 지도 위에 계속 표시했다.
  운영 API나 자료 상태는 변경하지 않았다.
- 더보기에서 모의훈련으로 전환해 보라색 훈련 안내, `모의훈련 · 실제 상황 아님`,
  훈련 기상 범례를 확인하고 실시간 화면으로 복귀했다.
- 자료 상태·더보기·검색·지도 설정·주변 시설은 각각 dialog 하나만 열렸고 닫은 뒤
  이전 지도 상태로 돌아왔다. 포커스 제한·복원과 Escape는 자동 행동 테스트로 보완했다.
- 통합 검색에서 `칠곡수질`을 검색해 `칠곡수질측정소`를 선택했다. URL은
  `?facility_id=3025`로 갱신됐고 접힌 시트에 등급·시설명·영향 특보·권장 행동이,
  펼친 시트에 기존 상세 정보와 `간단히 보기`가 표시됐다. 접힌 높이는 약 207px로
  390×844 지도 높이의 36% 이하였다.
- 장소 검색에서 `온산공단` 결과 8개를 확인했다. 결과를 선택하면 검색 입력·목록이
  사라지고 후보 핀과 확인 패널만 남았다. 긴 기준점 이름에서도 주소·다시 찾기·확정
  버튼이 잘리지 않았다.
- `지도에서 지정` 중 실제 지도 지점을 눌러 후보 핀과 `위치 다시 지정`을 확인했다.
  위치 선택만으로 기준점이 확정되지 않았다.

### 기준점·지도 설정·기상

- `온산국가산업단지`를 확정하면 전체 195개 시설 거리순 목록, 5km 이내 1개,
  10개 목록과 더 보기를 표시했다. `온산산단 대기측정소`를 선택한 390×844 화면에서
  기준점 `+`, 선택 시설, 거리 원, 점선 연결선, `직선거리 3.3km`와 접힌 시설 요약이
  모두 보였다.
- 상단 기준점 요약과 지도 핀 이름표가 겹치던 문제를 검수 중 발견해, 확정 후에는
  중복 지도 이름표를 숨기고 `+` 핀을 유지하도록 수정했다. 후보 이름표는 그대로 보인다.
- 지도 설정 시설 탭에서 유형·등급을 모두 꺼 `현재 0개 / 전체 195개 표시`와 복구 버튼을
  확인했다. 범례 탭에는 필터 입력이 없었고, 기상 탭 선택은 패널을 닫지 않았다.
- LIVE 바람을 켜고 패널을 닫은 뒤 `바람 실황`, 관측 시각, `0~25m/s+`, 풍향·풍속 설명,
  입자와 색면, 지도 설정 버튼의 `바람` 적용 표시를 확인했다.

### 중앙관제 회귀

- `/control`, `1440×900`, LIVE에서 운영 상황과 대상 분석·전파를 열었다. 기존 PC 표와
  Kakao 관제 지도에 가로 넘침이 없었다.
- 전파 대상 하나를 해제해 `선택된 시설: 194개소`로 만든 뒤 온산공단 기준점을 확정하고
  주변 시설을 선택했다. 기준점·거리 원·선택 시설·점선·`직선거리 3.3km`가 보였고
  전파 대상은 계속 194개소였다. 기준점 비교가 수동 전파 체크 상태를 바꾸지 않았다.

검수 중 만든 PNG는 `/tmp/phase5_*`에서 직접 확인했으며 저장소 산출물로 추가하지 않았다.

## 자동 검증

`field_web` 전체 27개 파일 186개 테스트와 프로덕션 빌드가 통과했다. 자동 테스트는
다음을 포함한다.

- LIVE·STALE·ERROR·SIMULATION 헤더와 안내, 새로고침 중복 방지, 모드 전환
- 모바일/PC 폭 변경 시 지도 인스턴스·선택·기준점 보존과 확대 컨트롤 교체
- 단일 패널, 포커스 제한·복원, Escape, 닫힌 검색의 늦은 응답 무효화
- 전체 시설 검색과 필요한 필터 자동 완화
- snapshot 갱신 시 사용자 그룹 선택 유지, 신규 그룹 추가, 삭제 그룹 정리
- 유형·등급 0개와 복구, 기상 선택·해제, 읽기 전용 범례
- 직접 지정→후보→확정→주변 시설→시설 요약과 취소 시 기존 기준점 복원
- 전체 시설 복귀의 필터·선택 초기화와 기준점·기상 유지
- 실제 DOM 가림 여백, 후보 핀·비교 범위 보정, 지도 드래그 시 불필요한 재맞춤 방지
- PC 현장 지도와 중앙관제 기준점·전파 선택 회귀

자동 검증을 실제 휴대폰 조작 검증으로 간주하지 않는다.

## 남은 실제 기기 확인

- 실제 휴대폰의 소프트 키보드, 노치·홈 인디케이터 safe-area, OS 접근성 글자 확대
- 실제 휴대폰 회전 중 브라우저 UI가 접히고 펼쳐지는 조건
- 운영 환경의 STALE/ERROR 자연 발생 화면. 이번 검수는 운영 상태를 바꾸지 않고
  브라우저 응답 복사본으로 표현만 확인했다.
- 실제 Telegram 전송, 강제 운영 갱신, 운영 배포는 수행하지 않았다.
