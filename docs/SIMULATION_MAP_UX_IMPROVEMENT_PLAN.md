## 1. 실화면 검수 결과와 확인된 원인

사용자가 운영 현장지도와 중앙관제를 PC·모바일 화면으로 확인한 결과 모의훈련의
특보·시설 영향·기상 그래픽 자체는 정상 동작했다. 다음 다섯 항목은 개선이 필요하다.

1. **태풍 시 기본 그래픽이 기온으로 열림**
   - `recommendedWeatherLayer()`의 태풍 → 바람 규칙은 맞다.
   - 그러나 `App.tsx`와 `ControlApp.tsx`는 모의훈련 진입 버튼을 누른 순간의 기존
     `data.warnings`로 추천 레이어를 고른다. 이때 모의훈련 snapshot은 아직 도착하지
     않아 실시간 특보를 참조할 수 있고, URL로 곧바로 훈련 모드에 들어오면 추천을
     다시 실행하지 않는다.
2. **기온·강수 그래픽이 지도를 지나치게 덮음**
   - 두 화면은 `KakaoMap.tsx`의 같은 canvas 렌더러를 사용한다.
   - 각 격자점의 반투명 방사형 색을 `source-over`로 반복해서 겹치므로 격자가 많은
     곳은 투명도가 누적돼 거의 불투명해진다. 현재 반경도 인접점 거리의 `0.78`이라
     겹침이 크다. 시설 주변만 잘라 내므로 지명·도로·행정구역은 가려진다.
3. **축소 화면의 바람 화살표가 적거나 일부 잘림**
   - 현재는 화면 격자마다 원본 배열에서 처음 만난 점 하나만 남긴다. 축소할수록
     여러 점이 한 칸에 몰리고, 칸 중앙이나 바람 세기와 무관한 점이 선택된다.
   - 화면 바깥 20px까지 허용해 가장자리 화살표 일부가 잘릴 수 있고, 지도 단계별
     고정 간격도 실제 화면 크기를 반영하지 않는다.
4. **중앙관제의 훈련 상태와 복귀 동작이 중복됨**
   - 상단 훈련 배너와 운영 상황 탭의 활성 훈련 패널에 같은 상태 설명과
     `실시간으로 돌아가기` 동작이 각각 있다.
5. **훈련 기상 범례의 문구가 중복되고 김**
   - 상단 배너가 이미 `모의훈련 / 실제 상황이 아닙니다`를 명확히 알리는데 범례도
     `(모의훈련 가정)`, `실제 관측이 아님`, 시나리오명을 한꺼번에 반복한다.

## 2. 목표와 제외 범위

### 목표

- 모의훈련 snapshot이 실제로 도착한 뒤 그 특보에 맞는 그래픽을 한 번만 자동
  선택하고, 사용자가 이후 수동으로 고른 레이어는 덮어쓰지 않는다.
- 기온·강수의 위험 분포는 알아볼 수 있으면서 지도 지명·도로·경계·시설 객체가
  계속 읽히게 한다.
- 화면 크기와 축척이 달라도 바람 화살표를 일정하고 대표성 있게 배치하며 잘림을
  방지한다.
- 훈련 상태·복귀 동작은 화면마다 한 곳에만 두고, 범례는 짧게 유지한다.
- 현장지도와 중앙관제가 공통 렌더링 규칙을 사용하고 PC·모바일에서 함께 검증된다.

### 제외 범위

- 모의훈련 특보 4건, 영향시설 31개소, 위험도 정책, 기상 시나리오 값 자체는
  변경하지 않는다.
- 서버 API, Worker, 자동알림 기준 상태, PDF, 실시간 현재 기상 카드는 변경하지
  않는다.
- 바람 입자 애니메이션, 예보 시간축, 지도 타일 교체, 사용자가 조절하는 투명도
  슬라이더는 추가하지 않는다.
- 실시간 자료와 모의훈련 자료를 섞거나 훈련 결과를 운영 실적으로 기록하지 않는다.

## 3. 확정할 UX 방향

### 훈련 상태와 범례

- 현장지도와 중앙관제 모두 **상단 보라색 배너**를 훈련 상태와 실시간 복귀의 단일
  기준으로 사용한다.
- 중앙관제 운영 상황의 훈련 진입 패널은 실시간 모드에서만 `모의훈련 시작` 용도로
  표시하고, 훈련 모드에서는 활성 패널 전체를 제거한다. 자동감시·운영 지표가 실제
  참고값이라는 설명이 꼭 필요하면 해당 지표의 보조문구에 한 번만 둔다.
- 훈련 중 compact 범례는 `바람 · 훈련값`처럼 **레이어명 + 짧은 훈련 표식 +
  척도/단위**만 보여준다. 시나리오명과 긴 `실제 관측이 아님` 문구는 항상 보이는
  범례에서 제거한다.
- 다만 스크린리더용 레이블과 레이어 선택 시트에는 `모의훈련 기상 가정이며 실제
  관측이 아님`을 유지해 안전 의미를 잃지 않는다.

### 기온·강수 그래픽

- 점마다 직접 화면에 합성하지 않고 별도 offscreen canvas에 기상장을 그린 뒤,
  visible canvas에 전체 투명도를 한 번만 적용해 겹침에 따른 불투명도 폭증을 막는다.
- 1차 조정 범위는 기온 전체 불투명도 `0.26~0.32`, 강수 `0.30~0.38`, 격자 반경은
  인접점 간격의 `0.50~0.58`이다. 이는 고정 정답이 아니라 실화면 수용 조건에 맞춰
  단계 2 안에서 조정할 시작 범위다.
- 강수량 0인 점 생략, 시설 주변 cutout, 고해상도 화면 보정은 유지한다. 단순히
  CSS canvas 전체 opacity만 낮춰 바람까지 흐려지게 하지 않는다.

### 바람 그래픽

- 보이는 점을 화면 격자로 묶고 `첫 점` 대신 **격자 중심에 가깝고 바람 세기를
  대표하는 점**을 결정적으로 고른다. 동일 입력·축척에서는 같은 화살표가 나와야
  한다.
- 간격은 지도 단계 하나만 보지 않고 canvas 너비·높이와 목표 밀도로 계산한다.
  시작 목표는 가로 기준 PC 7~12개, 모바일 5~8개이며 세로는 화면 비율에 맞춘다.
- 최대 화살표 길이와 외곽선을 고려한 약 20px 안쪽 영역에서만 중심점을 선택해
  가장자리 잘림을 막는다. 데이터가 충분한데 축소 화면에 몇 개만 남는 상태도
  방지한다.

## 5. 단계 운영 규칙

- 각 차례에는 다음 미완료 단계 **하나만** 구현한다.
- 시작할 때 Git·코드·계획의 짧은 대조는 하되 계획 전체를 다시 쓰지 않는다.
- 단계 종료 전에 diff를 검토하고 그 단계의 테스트를 통과시킨다.
- `docs/HANDOFF.md`에는 완료 단계, 남은 첫 단계, 변경 파일, 실행 테스트와 실패를
  현재형으로 남긴다. 미완성 단계를 완료로 표시하지 않는다.
- 한 단계가 검증 가능한 상태가 아니면 다음 단계로 넘어가지 않는다.
- 앱 코드를 수정한 커밋에 `[skip ci]`를 붙이지 않는다. push·운영 배포는 사용자
  요청을 확인한 뒤 수행한다.
