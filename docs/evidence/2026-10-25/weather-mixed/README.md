# 혼합형 기상 레이어 구현·실제 SDK 검수 — 2026-10-25 KST

사용자 선택 ③ 혼합형을 공통 레이어에 적용했다. 바람 A, 기온·강수 B다.
**운영 배포는 하지 않았다.** 앱/업무 API는 수정 빌드·고정 시설/합성 자료이고,
Kakao SDK와 타일만 실제 네트워크 응답이다. 이 결과는 운영 새 버전 검증이나 실제 휴대폰 검수가 아니다.

## 구현과 해결한 문제

- 약풍에는 A의 시각적 속도·꼬리·대비를 사용한다. 관측값·풍향·위험도는 바꾸지 않는다.
- 기온/강수는 alpha 0.108/0.126, 실제 격자값 최대 4개다. 마커·클러스터·범례·시설 카드와의 겹침을 피한다.
- 줌 시작 시 canvas를 숨기지 않는다. SDK 좌표는 최종 줌으로 먼저 바뀌므로 전환 중에는
  실제로 그려지는 앞쪽 타일 평면의 사각형으로 기존 그림을 같이 변환한다. 끝나면 같은 자료를 재투영한다.
  공개 DOM 사각형만 읽고 이미지 픽셀 추출·추가 타일 다운로드·SDK 비공개 메서드를 사용하지 않는다.
  타일이 없거나 재사용/제거되면 SDK 좌표 투영을 쓴다. SDK 버전 변경 시 이 전환을 다시 검수한다.
- localhost에서는 SDK HTTP 401이 발생했다. 같은 앱의 등록된 운영 원점에서 **응답만 로컬 수정 빌드로 대체**해
  SDK를 검수했다. 운영 HTML/JS·업무 API를 수정하거나 배포한 것이 아니다.
- 첫 좌표 방식은 줌 최종 위치로 먼저 뛰는 문제가 있어 타일 전환으로 보완했다.
  뒤쪽 캐시 타일 평면을 잘못 기준으로 삼는 문제도 앞쪽 평면 선택으로 해결했다.
- 검수 스크립트가 타일 로딩 완료 전에 캡처하던 문제를 고쳐 실제 표시 완료 후 다시 확인했다.
  초기 SDK 401과 검수 스크립트 실패를 환경 도메인 차단이나 앱 검증 통과로 섞지 않는다.

## 미검증·인계

스마트폰 실기기·실제 터치/핀치·장시간 배터리/발열, 운영 배포 후 실시간 기상 검수,
관리자 인증 후 화면은 미검증이다. 운영 dispatch·Worker·발송 시험·main push·배포는 하지 않았다.
별도 지도 서비스 도입이나 보고서의 도로 배경 추가도 하지 않았다. 그 추가 의견은
[보고서 문서](../../../NEARBY_FACILITY_REPORT.md)를 따른다.

재현: `field_web` 일반 빌드 후 [verify.mjs](verify.mjs)를 실행한다. SDK 앱 키의 등록 원점,
Chromium/Playwright/ffmpeg와 관리 환경의 HTTPS_PROXY가 필요하다.
환경변수 `WEATHER_APP_ROOT`, `WEATHER_CHECK_DIR`, `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `PYTHON`으로
경로를 지정할 수 있다. [시설 fixture 생성](export-fixture.py)은 CSV에서 연락처 없는 고정 응답만 만든다.
[좌표 관측 보조 코드](trace.js)는 샘플 측정용이며 제품 코드에 포함되지 않는다.
비밀값·키·쿠키·query·원시 운영 API 응답은 이 증빙에 보관하지 않았다. 외부 프록시와 TLS 검증을 유지했다.
