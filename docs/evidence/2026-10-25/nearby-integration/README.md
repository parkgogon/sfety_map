## 확인한 범위

- 실제 앱/API의 기존 `POST /api/v1/reports/nearby.pdf`·CSV 재계산·대상 수/digest를 사용했다.
  입력은 그대로이며 `X-Nearby-Map-Status`만 추가했다. 서버는 기준점·PDF를 영구 저장하거나 전파하지 않는다.
- SDK·지도 타일은 **실제 외부 응답**이다. 앱/보고서 정적 assets만 소유 사이트의 등록 원점에서 로컬 빌드로 대체했다.
  업무 자료는 실제 시설 CSV와 고정 모의훈련 관제 응답이다. 운영 앱/API 검증이 아니다.
  지도 공개 객체를 관찰해 검수 위치를 지정했으며 SDK의 지도 렌더링·투영·타일은 원래 동작을 유지한다.
- 백엔드도 같은 운영 캡처 클래스의 정적 페이지 응답만 개발용으로 대체했다. 실제 서비스 코드는 등록 원점의
  `report-map.html`을 연다. 응답 대체·`/__qa/*`는 개발 검수 도구에만 있으며 운영 이미지에 포함하지 않는다.
- 환경 [정책 revision 19](network-policy.json)는 current/enforced이며 SDK 3개 호스트와 소유 원점을 허용한다.
  HTTPS 프록시·TLS 검증을 유지했고 CA는 세션의 신뢰 체인으로 장착했다. 키·query·쿠키·헤더 원문은 증빙에서 제외했다.
- Chromium 자체 캡처 한 장에 도로·지명·기준점·반경·번호·북쪽·카카오 로고·축척을 보존했다.
  지도 픽셀의 CORS 허용 헤더를 바꾸거나 별도 타일 다운로드/병합을 하지 않았다.
- 한 줄 요약·4개 수치 카드·TOP5·거리/유형/부서 분포·거리순 전체 목록을 제공한다.
  실제 피해나 고위험 여부를 추정하지 않는다. 작은 보고서는 한 쪽에 모으고 0개소도 정상 출력한다.
- 최종 API PDF 0/1/3/41개소와 지도 시간 초과/사용 중 사례를 생성했다.
  [PDF 텍스트/페이지 검사](pdf-checks.json)에서 모든 시설명·페이지 범위·연락처 미노출을 확인했다.
  0/1/3 첫 쪽, 41개소 분석/마지막 쪽, 실패 안내 쪽을 렌더링해 직접 검토했다.
  밀집/동일 좌표·긴 한글/긴 행·도시/농촌/해안 × 5반경은 [앞선 시안 증빙](../nearby-preview/README.md)과 공통 렌더러 테스트에 있다.
- 현장/관제 각각 360/390/430/700/1440px에서 실제 기준점 지정·보고서 열기·다운로드를 조작했다.
  대상 3개소 일치, 생성 중 중복 제출 차단, 가로 넘침 없음, Escape 닫기·포커스 복원을 확인했다.
  현장 390px에서는 지도 실패 안내와 SDK 로딩 후 Escape 취소도 확인했다.
  [브라우저 기록](browser-checks.json)의 화면 오류·검수 네트워크 차단은 0건이다. 모바일 폭은 에뮬레이션이다.
- TCP 연결 종료 시 SDK 작업 정리 111ms, 브라우저 Escape 취소 시 검사 대기 포함 428ms였다.
  두 경우 모두 취소 후 완성 보고서 0건, 브라우저에서는 늦은 다운로드도 0건이다. 다음 생성이 정상 복구됐다.
  이미 실행 중인 PDF 스레드는 강제 종료하지 않고 실제 계산·슬롯 정리를 기다리는 테스트를 통과했다.

## 성능과 동시 요청

[API 실행 기록](api-checks.json), [컨테이너 한도·최고치](container-limits.json), [종료 전 서버 집계](server-final.json).
로컬 Docker의 실제 cgroup을 **1 CPU·1GiB(메모리/스왑 합계도 1GiB)**로 제한했다.

| 항목 | 최종 측정 |
|---|---|
| 지도 포함 PDF 생성 | 0/1/3/41개소: 5.31 / 5.38 / 6.29 / 6.13초 |
| 4건 동시 생성 | 지도 포함 1건·지도 실패 안내 PDF 2건·429 1건 |
| 동시 지도 캡처 | 인스턴스 내 최대 1건 |
| 메모리 | cgroup 최고 602.5MiB, 종료 후 약 238MiB |
| OOM / 잔류 프로세스 | OOM 0, 종료 후 Chromium·좀비 0개 |
| 병행 health 조회 990회 | 모두 200, 중앙값 2ms / p95 49ms / 최대 264ms |
| 지도 타일 의도적 실패 | 캡처 20초 후 목록·집계 PDF, 전체 응답 20.59초 |
| 지도 비활성/실패 | 목록·집계 PDF, 0.46초 |

보고서 요청 슬롯은 3건·PDF 계산은 1건이며 지도 슬롯 사용 중에는 목록 PDF로 진행한다.
API 이미지에만 Chromium/Playwright/tini를 포함했다. 별도 Worker 이미지의 브라우저 미포함도 로컬에서 확인했으며
Worker 앱/경로를 실행하지 않았다. 서비스 전체 캡처 1건 제한이나 Cloud Run에서의 부하 검증을 의미하지 않는다.

## 실패·차단과 해결

- 초기 반복 캡처에서 Chromium 보조 프로세스가 좀비로 남았다. API PID 1을 `tini`로 바꾼 뒤 반복 생성/취소를
  다시 실행했고 최종 유휴 상태는 tini·uvicorn·확인용 Python만 남았다.
- SDK 로딩까지 기다린 엄격한 취소 검사에서 기존 비차단 연결 확인이 종료를 놓쳤다.
  본문 파싱 뒤 실제 ASGI disconnect 이벤트를 기다리도록 고쳤고, TCP 종료·화면 취소 모두 완성 보고서 0건으로 재확인했다.
- 타일 실패 시험의 `mts.kakaocdn.net` 24건 `ERR_FAILED`는 **검수 도구가 의도적으로 차단**했다.
  환경 정책 차단이 아니다. 실패 PDF와 20초 제한을 확인하기 위한 시험이다.
- 정상 SDK/타일 응답은 서버 501건·화면 브라우저 501건 모두 HTTP 200이다.
  화면의 타일 `ERR_ABORTED` 41건과 보고서 요청 `ERR_ABORTED` 1건은 이동/화면 종료·의도한 취소 과정이다.
  새로운 환경 차단은 관찰하지 않았으며 **추가 허용이 필요한 호스트는 없다**.

## 자동 검증과 미검증

- Python **254개 통과**, 실제 외부 HTTP/TCP 0건: [로그](python-tests.log).
  반경 경계·동일 이름/좌표의 다른 ID·긴 한글/행·이미지 불일치·취소/과부하·기존 기상 차단을 검증했다.
  자동 테스트의 가짜 이미지/SDK는 실제 SDK 증빙과 구분한다.
- React **215개 통과**: [로그](web-tests.log). 데이터 195개 [검증](data-validation.log), Python 컴파일·[최종 웹 빌드](web-build.log)·문법·diff 검사도 통과했다.
- 마지막 빌드에서 지도 전용 폰트에 OFL 전문 메타데이터를 보존했다. 글리프/크기 테이블은 바꾸지 않았다.
  변경한 assets로 실제 SDK 캡처를 한 번 더 확인했다. [빌드·버전·폰트 확인](build-metadata.json), [캡처 재확인](font-smoke.json).
- 운영 배포 후의 정적 페이지/API 연동, Cloud Run 콜드스타트/실제 40개 동시 요청과 장기 부하,
  스마트폰 실기기·관리자 인증 후 기능·실제 외부 발송은 미검증이다.
- Geoapify 키 연결·국내 지도 품질·실제 지연/요금은 미검증 대안이다. 신규 가입/결제는 하지 않았다.
- main 병합/push·운영 배포/워크플로 수동 실행·Telegram/SMS·운영 dispatch/Worker/발송 시험 경로 호출은 하지 않았다.
