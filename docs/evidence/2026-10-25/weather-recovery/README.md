**시설 기상과 바람·기온·강수 실황이 모두 LIVE로 회복됐다.** 같은 API 이미지를 새 리비전에 기동한 뒤

## 실행한 복구와 근거 구분

- 사용자가 Cloud Shell에서 API만 같은 이미지 digest로 재배포하고 `--to-latest`를 실행했다.
  새 리비전은 `safety-dashboard-api-kma-refresh-20261025101443`, 트래픽 100% LATEST다.
  [리비전/트래픽 근거](recovery-deployment.json)는 **사용자 제공 콘솔 결과**이며 관리 환경의 직접 GCP 조회가 아니다.
- 앱/웹 소스는 `616d7a2`로 같고, 운영 화면의 버전도 그대로다. 앱 코드·이미지 빌드·웹·Worker·Scheduler 배포는 하지 않았다.
  같은 이미지/설정 참조를 유지하는 복구였으며 KMA Secret 값 변경·TLS 완화·프록시 우회는 하지 않았다.
- 관리 환경 revision 33/current/enforced, 기존 프록시·CA/TLS 검증을 유지했다.
  관리 환경에 GCP identity/gcloud가 없어 제어 영역 설정/출구 IP 직접 조회는 실행하지 않았다.
  별도 Job·로컬 원본 성공과 구분한 **실제 운영 API/브라우저 성공**은 아래 증빙으로 확인했다.
- Telegram·SMS 시험 발송, 운영 수동전파·Worker·dispatch·발송 시험 경로 호출은 0건이다.
  검수 브라우저는 허용한 읽기 경로 이외를 요청 가드로 차단하며 응답을 대체하지 않는다. 관리자 인증도 입력하지 않았다.

## 남은 개선 후보·미검증

- 광역 축척의 바람 입자가 일부 클러스터 숫자 위를 지나가는 표현은 **가독성 개선 후보**다.
  위치/기상 자료 오류로 확인한 것은 아니며 이번 복구에서 앱 코드를 수정하지 않았다.
- 재기동 후 실황 회복은 확인했지만 **기존 운영 인스턴스의 정확한 DNS/출구 장애 원인과 장기 재발 여부는 미확정**이다.
  KMA 목적지 IP 변화와 우리 출구 IP를 혼동하거나 특정 IP의 상시 차단으로 단정하지 않는다.
- 스마트폰 실기기 터치/핀치·장시간 배터리/발열·극한 기상 전체 범위·관리자 인증 후 기능·운영 동시 부하/메모리 최고치는 미검증이다.
  검수 범위에서 현재 실황/지도/PDF 사용을 막는 실패는 남지 않았다.

앱/배포 코드를 바꾸지 않았으므로 이미 통과한 제품 자동 테스트를 재실행하지 않았다.
검수 스크립트의 문법·증빙 링크/해시·비밀값 미포함을 확인했다. [SHA-256](SHA256SUMS).
