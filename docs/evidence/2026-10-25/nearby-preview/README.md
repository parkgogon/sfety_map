## 확인

- 개발 HTML/폰트 응답을 소유 사이트의 등록 원점에서 대체하고 **SDK·타일은 실제 응답**을 사용했다.
  운영 앱/API 검수가 아니다. JavaScript 키의 등록 원점을 재사용한 개발 검증이며 이 응답 대체를 운영 캡처 방식으로 구현하지 않는다.
- 정책 revision 15/current/enforced에서 `dapi.kakao.com`, `t1.kakaocdn.net`, `mts.kakaocdn.net`을 확인했다.
  실제 SDK/타일 HTTP 200은 각각 16/64/384건, 합계 464건이다. 실패 요청·페이지 오류·검수 차단 요청은 모두 0건이다.
  query·키·헤더·쿠키를 제외한 [최종 캡처 기록](capture-results.json)을 보관했다. 추가 허용이 필요한 실패 호스트는 없다.
  별도 [타일 헤더 확인](tile-header-checks.json) 2건도 HTTP 200이지만 캔버스 내보내기용 CORS 허용 헤더는 없었다.
- Chromium의 브라우저 자체 캡처로 1200×620 CSS px, DPR 2의 단일 지도 PNG를 만들었다.
  이미지 타일을 따로 내려받거나 병합하지 않았다. 환경 HTTPS 프록시와 TLS 검증을 유지했다.
  카카오 로고·축척을 원본대로 포함하고 북쪽·기준점·반경·번호를 표시했다.
- 도시(대구 동인동)·농촌(의성읍)·해안(포항) × 0.1/1/3/5/50km의 15개 조합과 합성 195개소 입력을 확인했다.
  원이 화면 안에 들어오고 번호 배지 잘림·겹침은 0이다. 시설 좌표는 점으로 보존하며 번호를 옮길 때만 연결선을 그렸다.
- 기존 `NearbyReport`의 CSV 선정·Haversine 직선거리·반올림 전 경계 포함을 재사용했다.
  지도·요약·목록의 시설 ID/좌표/반경/분류 합계와 PNG SHA-256을 대조해 다른 이미지나 시설 자료를 거절한다.
  동일 이름·동일 좌표도 ID별로 보존했다. 반경·필터·전파·KMA와의 독립성을 바꾸지 않았다.
- 한 줄 요약·4개 KPI·큰 지도·가까운 시설·거리대/유형/부서 막대·거리순 전체 목록을 넣었다.
  CSV의 원문 유형으로 집계하므로 앱의 7개 유형 그룹과 종류 수가 다를 수 있다.
  실제 피해·위험도·도착 시간·사건 유형을 추정하지 않았다.
- 실제 PDF 16개를 생성하고 텍스트/페이지 경계/연락처 미노출을 확인했다. [PDF 검사](pdf-checks.json), [시간·크기](pdf-results.json).
  렌더한 대표 0·1·3개소, 다수 첫/분석/마지막 쪽, 해안 첫 쪽, 합성 긴 행의 시작 5쪽·종료 8쪽과 마지막 10쪽을 직접 검토했다.

  0m/1·3·5km 구간 경계, 임의 반경, 중복 ID/좌표·다른 이미지 거절, 긴 행 분할·마지막 내용, 실제 3개소 1쪽 배치를 검증했다.

## 실패 후 해결

- 첫 캡처는 다수 시설의 번호 배지가 겹쳤다. 실제 위치를 유지한 안내선 배치로 보완하고 최종 16개 조합을 다시 검증했다.
- 검수 메타데이터에서 시설 배열을 시설 수로 덮어쓰는 버그를 고쳤다. `facilityCount`로 분리하고 전 조합을 다시 캡처했다.
- 실제 3개소 PDF의 분석만 다음 페이지로 넘어가던 배치를 고쳤다. 본문 간격과 실제 가용 높이를 맞추고 1쪽 회귀 테스트를 추가했다.
  최종 0·1·3개소는 1쪽이다. 해안 4개소는 주소·담당부서·분석 분량 때문에 2쪽이다.
- 관리 브라우저가 비교 HTML의 `file://` 탐색을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 막았다.
  검수 HTML/이미지만 소유 원점에서 응답 대체하는 방식으로 확인했다. 브라우저 정책·프록시·TLS 설정을 변경하지 않았다.

## 성능과 운영 적용 판단

- 기본 캡처 16개: 브라우저 시작 216ms, 지도 캡처 중앙값 **2648.5ms**, 최대 **4303ms**.
  개선 PDF 조립은 **446~671ms**였다. 네트워크·폰트 로딩을 포함한 개발 환경 관측이며 SLA가 아니다.
- 같은 Linux 논리 CPU 하나에 고정한 별도 병행 측정: 기존 PDF 중앙값 **389.5→800.0ms**,
  p95 **405.4→1252.3ms**(기준 8건/병행 22건). health 중앙값은 **1.2→1.4ms**였다.
  그때 지도 캡처 3건은 6009/5126/3552ms였다. [측정](benchmark-results.json).
- 기본 측정의 브라우저 최고 PSS는 **377MiB**, 병행 측정에서는 **385MiB**였다.
  API 프로세스의 기준 PSS는 **156.1MiB**였다. RSS 합계는 공유 페이지를 중복 계산하므로 PSS와 구분한다.
  현재 배포 설정은 API 1 CPU/512Mi/동시 요청 40이다. 이 설정에 무제한 캡처를 추가하는 방식은 적합하지 않다.
  운영 통합 전 동시 캡처 제한·실행 자원·콜드 스타트를 확정하고 제한된 컨테이너에서 다시 검증해야 한다.
  이번 값은 별도 시점/프로세스 관측이며 Cloud Run 메모리 한도·실제 운영 부하 검증이 아니다.
- 이번 범위에서는 API/Worker 이미지·인프라·공개 API 명세·서비스 계정·환경 설정을 변경하지 않았다.
  개발 이미지와 보고서만 승인된 증빙으로 보관했다. 제품의 서버 저장·자동 전파 기능은 추가하지 않았다.

## 대안 API 검토

2026-10-25 공식 문서 기준:

- 카카오의 [필요한 일부 지역 업무용 캡처 안내](https://devtalk.kakao.com/t/javascript-sdk-png/152174)와
  [오프라인 출처 가이드](https://kakaomap.tistory.com/257)를 확인했다.
  구독형 약도 서비스의 이미지 다운로드 제한 답변을 모든 화면 캡처 금지로 일반화했던 이전 설명을 수정했다.
- Geoapify는 [정적지도 저장·인쇄](https://www.geoapify.com/static-maps-api/)를 허용하며,
  [API 문서](https://apidocs.geoapify.com/docs/maps/static/)에 한글(`lang=ko`)·범위·해상도·반경 표현을 제공한다.
  [요금 산식](https://www.geoapify.com/pricing-details/)은 요청 1 credit + 타일 수/4 + 마커 아이콘 수다.
  예를 들어 1200×620 기본 크기·아이콘 없는 배경은 공식 근사식으로 1+5×3/4=4.75 credits다.
  고해상도 출력·타일 경계·아이콘에 따른 실제 청구량은 별도 확인해야 한다.
  기본 무료 구간은 일 3000 credits이며, 이는 지도 3000장과 다르다. 필수 출처 표시도 유지해야 한다.
- Geoapify 키는 발급·연결하지 않았다. 실제 요청·국내 도로/지명 품질·지연·실청구는 **미검증**이다.
  카카오 캡처의 구현/운영 부담과 비교할 대안으로 남겼으며 채택·결제·운영 연결은 하지 않았다.
