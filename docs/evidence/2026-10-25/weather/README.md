# 기상 비교 시안 증빙

이 폴더는 개발 시안 산출물이다. 운영 앱 검수·실제 SDK 정합·실기기 검수가 아니다.
**기상 입력 전체가 합성이고 배경은 자체 개략도다.** 실제 자료를 변조하거나 실제 관측 검증으로 표시하지 않았다.
현재 안은 기존 렌더러·색상 토큰을 재사용하며 줌 이벤트 동작은 모사한다.

## 확인

- [프리뷰](preview.html)는 단일 HTML로 PC/모바일에서 움직인다. 별도 API·지도 SDK·폰트/CDN 요청이 없다.
- [PC 영상](wind-1440.mp4)과 [모바일 영상](wind-390.mp4)은 프리뷰 브라우저의 연속 캡처로 생성한
  15초·12fps H.264다. 0~3초 무풍, 3~7초 약풍, 7~11초 강풍, 11~15초 약풍에서 이동·줌이다.
  모바일은 같은 단계에서 현재/A/B를 순환한다. ffprobe로 두 영상의 길이 15초를 확인했다.
- 같은 상태에서 현재/A/B의 바람·기온·강수 PC 3장, 모바일 9장을 캡처했다.
  모든 레이어의 PC 화면과 모바일 B를 직접 봤으며 무풍·약풍·강풍·줌 연속 프레임도 직접 검토했다.
  약풍에서 현재보다 A/B 흐름선이 명확하고 0m/s에는 흐름이 없다. B의 옅은 색면과 숫자도 비교했다.
  이것은 후보의 관찰이며 채택 판정이 아니다.
- 직접 조작: 바람/기온/강수 변경, 풍속 변경, 탭, 드래그 +35/+20px, 확대 1.2배,
  움직임 줄이기와 시설 카드 배치 예시. 카드와 범례의 겹침이 없었다.
  [모바일 카드 예시](card-390.png), [PC 카드 예시](card-1440.png). 1440·390px 가로 넘침 0, pageerror 0.
  [조작 기록](interaction-results.json), [영상 상태·외부 요청 0](results.json).
- 별도 TypeScript 검사·시안 빌드 통과. 일반 앱 빌드는 시안 진입점·문구를 포함하지 않는다.

## 검토 중 해결

- 첫 시안의 약풍 선이 희미해 대비·꼬리를 조절하고 다시 캡처했다.
- 숫자 한 곳이 범례 아래로 들어가 후보 위치를 4곳으로 정리했다.
- 모바일 숨은 탭도 같은 시간으로 진행하도록 고쳤다.
- 현재 안에 앱 색상 토큰을 함께 로드해 코드의 기본색 대신 실제 현재 색상을 사용하도록 맞췄다.
- 시안 빌드 초기에 CSS 선언 형식이 빠진 오류는 별도 tsconfig의 vite/client 타입으로 해결했다.

## 미검증

실제 Kakao 도로 위 읽기·자료 재투영·이동/줌 성능, 실제 관측값 대조, 실제 시설 카드와 수치 충돌,
스마트폰 실기기 성능·접근성은 아직 미검증이다. 운영 표현은 변경하지 않았다.
추가 외부 차단 호스트는 없다. API·SDK 외부 요청 자체를 하지 않는다.

재현: `field_web/design/weather/capture.mjs`와 [조작 스크립트](interaction-check.mjs).
스크립트의 Playwright/Chromium 경로는 이 환경 기준이며 환경변수로 바꿀 수 있다.
외부 프록시는 유지하며 localhost 검수 서버만 로컬로 연결했다.
단일 파일 재생성·비교 수치·선택 기준은 [시안 검토](../../../WEATHER_VISUAL_REVIEW.md)를 따른다.
