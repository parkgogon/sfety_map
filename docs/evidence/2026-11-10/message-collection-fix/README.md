- [gen2 격리 재현](https://github.com/parkgogon/sfety_map/actions/runs/42698311583): 같은 운영 이미지·계정·기존 키 버전으로 2페이지 조회 성공, 메모리 기록 1, 잔여 파티션 1. 최대 2페이지의 정상 partial이며 전체 수집 완료 검사가 아니다.

처음 두 재현은 실행 환경을 명시하지 않았으므로 gen1 인과관계를 확정하지 않는다. gen1을 명시한 대조와 수정 후보의 gen2 재현은 최종 결과에 추가한다.

연결의 낮은 수준 원인·장기 안정성은 아직 미확정이다. 다음 배포 설정의 문자 worker만 gen2로 명시하며 CPU 1/512Mi·최소 0/최대 1·기존 예약을 유지한다. 단순 재시작 성공을 해결 보장으로 표시하지 않는다.

## 정렬에 의존하지 않는 수집

- `recent_window_v2`는 당일 첫 페이지가 같아도 뒤 페이지를 매 순회 다시 읽는다. page 1의 hash로 나머지 페이지를 생략하지 않는다.
- 중단한 페이지/행은 원장에 보존하며, 응답이 바뀌면 해당 페이지 처음부터 중복 제거하며 다시 읽는다. 자정에는 당일을 먼저 시작하고 전일의 미완료 작업도 보존한다.
- 기존 5분 예약은 순회 진행 기회다. 당일 1페이지는 5분, 2페이지는 10분, 3페이지는 15분 등 완료한 페이지/재시도 수에 따라 다음 순회 간격을 늘린다.
- 기본 450회/최근 24시간 안에서 당일 289회 몫과 보충 161회 몫을 유지한다. 작은 사용자 설정에도 과거 자료 몫을 남긴다. 빠른 모드는 한 실행 최대 페이지와 조회 한도가 각각 2 이상이어야 한다.
- 정상 1페이지·2페이지 모형은 모두 당일 288회+전일 24회=312회/24시간이다. 실제 추가 페이지·실패·지연·재시작은 별도로 예산을 소비한다.
- 과거 자료는 시간마다 새 전체 순회를 시작하며 미완료 페이지는 이어간다. 한 번의 페이지 순회는 제공자 자료의 원자적 snapshot이 아니다. 순회 중 이동/늦게 공개된 자료는 다음 순회에서 확인될 수 있고 지연 상한을 보장하지 않는다.
- 마지막 당일 끝페이지 도달과 과거 완료를 분리해 표시한다. 첫 페이지만 성공한 결과를 전체 최신 수집으로 표시하지 않는다. 처리 오류는 단계만 남기며 원문/키/원본 예외를 기록하지 않는다.
