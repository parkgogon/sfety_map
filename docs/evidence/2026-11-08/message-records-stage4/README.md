## 구현과 검증 범위

- 기존 기록에서 추가/정정/해제 관련 후속 문자를 수동 연결하고 종류·확인 사유·버전을 저장한다.
  각각의 원문/분석과 기존 시설 선정은 유지한다. 연결 해제도 사유를 남기며 기록을 삭제하지 않는다.
- 두 문자의 출처·발행 시각·수신지역·원문과 구간별 인용·시각·장소 역할을 나란히 보여준다.
  유일한 역할/표기 일치만 대조하며 실제 같은 장소라는 증명으로 해석하지 않는다.
  다른 표기·중복·누락은 별도 표시하고 일부 해제를 전체 해제로 처리하지 않는다.
- 명확히 다른 수신지역은 추가 광역 상황 확인/근거가 필요하다. 지역 미상은 추정하지 않는다.
  창작은 창작끼리만 연결하며 모든 연결에 관리자 확인/사유를 요구한다. 무관한 사건을 자동 판별하는 모델은 아니다.
- 연결/재확인/해제는 완료/초안을 무효화한다. 후속 원문/분석/연쇄 연결 변경도 완료/복사 시 동적으로 검사한다.
  직접 연결·연쇄 연결의 확인과 구간별 보완 메모로 재검토한다. 연결을 되돌려도 옛 완료가 복구되지 않는다.
- 연결 정보와 변경 이력은 기존 기록 한 건의 트랜잭션으로 저장한다. 대상 기록과의 원자 갱신은 주장하지 않는다.
  비교 뒤 대상이 바뀌면 다음 조회/완료/복사 시 재확인 대상이다.
- 불변 순서로 역방향/순환을 막고 직접 10건·연쇄 4단계·전체 30건 한도를 적용한다.
  Firestore 일괄 조회 순서가 달라도 완료 근거 해시는 일정하다.

## 브라우저

실제 로컬 React → FastAPI → CSV/메모리 저장소를 연결했다.
가람교/푸른교 두 문자는 **작성한 창작 시나리오**, 분석은 **직접 작성한 가짜 제공자 응답**이다.
분석 인용은 해당 원문에 포함된 구절이며 모델 이름도 `local-scripted-fixture`로 표시했다.
이번 브라우저 검수는 실제 AI의 해석 정확도 평가가 아니다. 실제 모델/장소 검색 평가는
[앞선 별도 증빙](../disaster-message-ai/README.md)을 참고한다.
지도는 가짜 SDK이며 실제 SDK·타일을 요청하지 않는다.

1. 두 교량 통제 문자 등록/분석/완료와 후속 일부 해제 문자 등록/분석.
2. 원문 비교에서 가람교 해제·푸른교 유지 확인 → 사유/확인 후 연결 → 과거 완료/초안 무효화.
3. 원래 원문/분석과 별도 후속 기록 불변 확인. 구간 보완 메모 필수 → 새 초안에 두 원문/주의 문구 반영.
4. 서버 검사 후 격리된 Chromium 클립보드 쓰기/읽기와 새로고침 복구. 추가 분석 없음.
5. 후속 재분석만으로 부모 버전이 그대로인 이전 초안 복사 409 → 화면 재확인 필요 → 명시적 재확인/다시 완료.
6. 사유를 남겨 연결 해제 → 두 기록 유지 → 과거 연결 사유/확인 분석 버전 읽기 전용 열람.
7. 1440/390/360px 비교 화면 가로 넘침 없음. 페이지 오류/예상 밖 요청 0건.

가짜 분석 요청 3회(원문/후속/후속 재분석), 복사 근거 확인 2회(성공 1, 후속 변경 후 거부 1)다.
새 OpenAI/Kakao 호출·실제 발송 **0건**이다. 모바일은 viewport 에뮬레이션이며 실기기가 아니다.
운영 Firestore/공식 API/실제 SDK·서버 비밀값 연결/운영 배포는 미검증이다.
KMA 등급/관제 상태/Worker/Scheduler/전파 설정은 변경하거나 시험 호출하지 않았다.
