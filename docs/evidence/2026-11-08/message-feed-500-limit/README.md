# 공식 문자 일일 500회 대응 검수

사용자가 SafetyData의 본인 일일 호출 한도를 **500회**로 확인했다.
기존 지역별 5분 조회안은 첫 페이지만 2,880회/일이므로 수정했다. 운영에는 아직 반영하지 않았다.

전국 자료를 날짜별로 한 번씩 받아 실제 수신지역이 소관 5지역에 걸치는 문자와 전국 문자를 선별한다.
본문 지명으로 대상을 만들지 않는다. 확인할 수 없는 수신지역은 부분 조회로 남긴다.
정상 주기는 **15분**, 회당 최대 **4페이지**이며, 나머지 진행은 저장해 이어간다.

자동·관리자 수동 조회가 같은 Firestore 기록을 사용해 **최근 24시간 최대 450회**로 제한한다.
HTTP 전에 예약하며 실패/타임아웃도 집계하고 저장소 장애 시 호출하지 않는다. 날짜가 바뀌어도 일괄 초기화하지 않는다.
나머지 50회는 외부 점검 등을 위한 여유다. 앱 밖에서 발생한 요청은 이 기록에 포함되지 않는다.
조회 한도 대기·재조회 가능 시각을 AI 분석 20건/일과 구분해 표시한다.

## 검증

[요약](test-summary.json): Python **523개**·React **268개**, compileall·CSV **195개소**·웹 빌드·배포 셸 문법 통과.
자동 검사의 실제 외부 HTTP/TCP 시도 **0건**이며 이번 변경에서 새 실제 SafetyData/모델/장소/발송 호출은 하지 않았다.
이전 실제 서버 검수는 [별도 증빙](../safetydata-registration-preflight/runtime-check.json)에 보존한다.

주요 검사는 동시 API/worker 예약의 원자성·450회 차단·24시간/자정 경계·상한 축소 후 재개 시각,
HTTP 실패 차감·저장소 오류 시 미호출·리디렉션 거부·수동/자동 공통 기록,
전국 2조회로 10지역별 조회 대체·여러 수신지역 보존·비소관 제외·지역 미상 부분 처리,
정확한 하루/시작일 이후 응답 호환·한도 대기 중 진행 보존/재개·429/503/no-store,
15분 예약과 잘못된 호출 상한/페이지 수/주기 설정 거절을 포함한다.

## 화면 통합 검수

실제 로컬 빌드 React/API/시설 CSV와 메모리 기록/상한 저장소, 가짜 공식 피드·합성 분석·가짜 지도 SDK를 연결했다.
브라우저 진입 전 수집/분석 → 추가 수신 후 읽기 갱신 → 한 화면 승인과 미승인 입력 보존을 확인했다.
상한 기록을 450회로 만든 뒤 다음 수집을 실행했을 때 가짜 제공자 접근/새 원문/추가 분석이 발생하지 않았고 진행 위치는 보존됐다.
화면에서 조회 한도 대기와 450/450회·15분, 별도의 2/20건 AI 사용량을 대조했다.
상태 조회 실패 때 기존 목록도 유지됐다. [브라우저 결과](browser-checks.json).

1440/390/360px 모두 가로 넘침 없음. 화면 오류/예상 밖 요청 **0건**.
가짜 피드 요청 4회·가짜 분석 2회이며 브라우저의 분석 요청은 0회다.
실제 운영 Firestore 상한 경쟁·정규 예약 실행·실기기 검수는 기능 배포 후 확인 대상이다.
