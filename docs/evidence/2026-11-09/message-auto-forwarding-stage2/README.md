## 저장 경계

원본 commit에 `notification_dirty`를 함께 남겨 분석 완료 후 별도 저장이 끊겨도 재처리할 기록을 찾는다.
원본과 판단/작업을 교차 읽고 근거 버전을 검사한 뒤, 판단·작업 저장과 표식 해제를 같은 트랜잭션으로 수행한다.
표식 해제는 사람의 버전/검토 상태/변경 이력을 늘리지 않고 최근 공식 관측 메타데이터도 보존한다.

원문 버전마다 작업 ID는 하나다. 분석 전 임시 기록은 최초 최종 판단을 소진하지 않는다.
원문 정정은 이전 대기를 무효화하고 새 버전으로 판단한다. 같은 원문을 재분석하거나 정책/시설/수동 근거를 바꾸면
기존 대기는 무효화하며 자동 재등록하지 않는다. 재고가 필요한 경우 `reconsideration_required`로 구분한다.
전달 성공/결과 미상 상태는 검사에서 주입한 값이며 실제 Telegram 처리를 검수한 것이 아니다.

새 기능은 `MESSAGE_NOTIFICATION_PREPARATION_ENABLED=false`가 기본이다. 실제 설정을 켜거나 키/예약/기상 기준을 바꾸지 않았다.
준비 활성화 시각은 처음 한 번 보존하고 이전 발행 자료는 대기 생성에서 제외한다.
모든 작업은 `phase=preview`, `dispatch_enabled=false`이고 `delivery_started_at=null`이다.
실제 전달 시작 경계와 전송은 후속 단계이며, preview 작업을 운영 전파로 자동 승격하지 않는다.
