# 기능 인벤토리

- 문서 상태: v3 구현 기준
- 기준 구현: `app.py`, `app_v2.py`
- 대상 버전: v3

## 1. 판정 기준

- **유지**: 업무 목표에 직접 필요하고 현재 검증 자산을 재사용할 수 있음
- **변경**: 필요하지만 위치·흐름·책임을 다시 설계해야 함
- **제외**: 현재 목표에 기여하지 않거나 중복됨
- **보류**: 제품 방향 결정 또는 저장소가 필요함

## 2. 기능 목록

| 영역 | 현재 기능 | v3 판정 | 정리 방향 |
|---|---|---:|---|
| 특보 | KMA 실시간 특보 조회 | 유지 | 순수 KMA 클라이언트와 캐시를 분리 |
| 특보 | 지역명 문자열 필터 | 제외 | 공식 `region_code` prefix로만 1차 범위 결정 |
| 경계 | 공식 특보구역 GeoJSON 조회 | 유지 | provider 밖의 경계 repository로 분리 |
| 경계 | 내장 gzip fallback | 유지 | 최신 시각과 fallback 상태를 명시 |
| 시설 | CSV 시설 목록 | 변경 | v3 초기에는 유지하되 repository 인터페이스 뒤로 숨김 |
| 시설 | 주소·좌표 검증 | 유지 | UI가 아닌 repository/domain validation으로 이동 |
| 매칭 | 공간 도형 포함 판정 | 유지 | 핵심 도메인 서비스로 분리 |
| 매칭 | 주소 문자열 fallback | 변경 | 코드·공간 판정 불가 시에만 사용하고 근거 기록 |
| 위험도 | 특보 종류별 가중치 | 변경 | 직접 읽을 수 있는 종류×단계 TOML 표로 교체 |
| 위험도 | 여러 특보 중 최고점 사용 | 유지 | 가장 높은 등급 채택, 모든 근거 보존 |
| 위험도 | 상·중·하 분류 | 변경 | 등급별 의미·권장 행동을 정책 파일에 정의 |
| 지도 | 시설 마커와 클러스터 | 유지 | marker popup과 우선순위 목록을 함께 제공 |
| 지도 | 특보 폴리곤 | 유지 | 최고 단계 색상만 표시, 전체 특보는 상세에서 제공 |
| 지도 | 시설·특보 필터 | 변경 | 6개 시설 그룹과 5개 위험도 다중 선택을 지도 위에 제공 |
| 요약 | 활성 특보 수 | 유지 | 상단 요약 한 곳에서만 표시 |
| 요약 | 최고 특보 단계 | 유지 | 상단 요약 한 곳에서만 표시 |
| 요약 | 영향 시설 수 | 유지 | 상단 요약 한 곳에서만 표시 |
| 요약 | 데이터 상태 카드 | 변경 | 카드가 아니라 헤더 상태 표시로 이동 |
| 특보 | 별도 특보 요약 배너 | 제외 | 점검 패널의 특보 목록으로 통합 |
| 대응 | 점검 우선순위 카드 | 유지 | 화면의 기본 패널로 유지 |
| 대응 | 전체 대상 테이블 | 변경 | 체크박스 표를 Telegram·PDF 공통 대상 기준으로 사용 |
| 대응 | 점검 상태 | 제외 | 조회·발송·보고서 범위에는 저장하지 않음 |
| 알림 | 수동 텔레그램 발송 | 유지 | 미리보기·확인 후 발송, 결과는 현재 화면에만 표시 |
| 알림 | 메시지 자동 분할 | 유지 | notification service 내부 책임 |
| 알림 | 자동 반복 발송 | 제외 | 승인 없는 자동 발송은 첫 배포에서 제외 |
| 시설 상세 | 담당자·유형·주소 | 유지 | 선택 시설 상세 패널에서만 표시 |
| 시설 상세 | 현재 기상 | 제외 | 조회·발송·보고서 핵심 범위에서 제외 |
| 보고서 | PDF 생성 | 유지 | UI와 독립된 report service로 이동 |
| 보고서 | HTML 전체 미리보기 | 제외 | 화면 중복을 줄이고 요약+PDF 다운로드만 제공 |
| 전역 제어 | 새로고침 | 유지 | 마지막 성공·시도 시각을 함께 표시 |
| 전역 제어 | 상단 보고서 버튼과 보고서 탭 | 변경 | 탭 제거, 조회 결과 아래 작업창 버튼으로 통합 |
| 훈련 | 모의훈련 toggle | 변경 | 운영 화면에서 명확한 훈련 배너와 별도 권한 사용 |
| 확장 | provider registry | 보류 | 실제 두 번째 provider가 생길 때 도입 |
| 확장 | 특보 이미지 URL·bounds | 제외 | 현재 UI에서 사용하지 않음 |
| 레거시 | `app.py` | 제외 | v3 동등성 검증 후 삭제 |
| 레거시 | `app_v2.py` | 제외 | v3 전환 후 삭제하고 단일 진입점 사용 |

## 3. 핵심 기능 묶음

v3의 기능은 다음 네 묶음만 상위 개념으로 사용합니다.

### 상황 파악

- 데이터 상태
- 활성 특보
- 영향 시설
- 최고 위험도

### 시설 판단

- 시설·특보 공간 매칭
- 위험도와 근거
- 지도·목록 선택
- 시설 상세와 적용 특보

### 대응

- 점검 대상 선택
- 알림 미리보기와 발송

### 보고

- 상황 요약
- 위험 시설 목록
- PDF 생성

## 4. 기능 추가 원칙

새 기능은 다음 질문에 모두 답할 수 있어야 합니다.

1. 어떤 사용자의 어떤 결정을 돕는가?
2. 기존 화면의 어느 정보를 대체하는가?
3. 필요한 입력과 실패 상태는 무엇인가?
4. domain, service, adapter, UI 중 어디에 속하는가?
5. 자동 테스트 가능한 수용 조건은 무엇인가?

답이 없는 기능은 바로 구현하지 않고 인벤토리의 `보류`에 먼저 추가합니다.
