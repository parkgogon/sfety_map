# 재난문자 AI 검토 — 첫 시연 단계

기준: 2026-11-07, main `65f0d4f`, 작업 브랜치 `feature/disaster-message-ai`.
정형 KMA 특보의 규칙 판정은 유지하고, 비정형 문자에서 장소·상황·시점을
구분하는 보조 기능을 추가한다. 기존 보고서/전파 기능과 중복하지 않는다.

## 단계와 수용 조건

1. **첫 시연 (구현·로컬 검증 완료, 미배포)**: 관리자 화면에서 직접 입력한 문자와 발행 시각을
   OpenAI Responses API로 해석한다. 모델이 장소 검색, 주변 시설 조회,
   분석 제출 중 필요한 도구를 선택하고 조회 결과를 받아 다음 행동을 정한다.
   예방/사고/예정 통제/해제, 사고 장소/대피 목적지를 나누고 원문 근거를 표시한다.
   다중 구간은 각각 유지한다. 시설은 CSV ID와 계산한 거리만 사용한다.
   시간은 한국 시간의 발행 시각을 기준으로 해석하고 미상은 미상으로 남긴다.
   자동 테스트는 가짜 OpenAI·장소 제공자로 검증한다. 실제 API 의미 정확도는
   별도 실제 API 평가로 구분하며 모의 응답 성공을 실제 AI 성공으로 세지 않는다.
2. **실제 모델 평가 (OpenAI·Kakao 창작 예문 점검 완료)**: GitHub Secrets의 키를 평가 워크플로에 연결하고 창작 예문 6종 및 추가 반례로
   분류·장소 역할·부분 해제·상대 시점·보류·조회 선택을 사람이 판정한다.
   지정 점검·걸린 시간·비용·실패를 기록한다. 모호한 위치는 질문으로 보류한다.
   최종 실제 응답 6종의 지정 점검을 재평가로 통과했으며 원본/실패도 보존했다.
3. **운영 연결 판단**: 재난문자 API 사용/가공 조건, 수집 누락·정정·중복·해제
   연결을 확인한 뒤 실제 수집과 검토 이력을 별도로 설계한다.

## 이번 단계의 경계

- 수동 입력 및 창작 예문만 사용한다. 실시간 문자 수집, 발송, 담당자 회신,
  위험등급 변경, 피해 예측, 대피 경로 추천은 포함하지 않는다.
- 위치 검색은 선택적 `KAKAO_REST_API_KEY`가 있을 때만 가능하다.
  지도 JavaScript 키와 별도다. 미설정/장애/검색 0건은 위치 미확인이다.
- 장소 후보는 실제 검색 응답에서 생성한 ID로만 참조한다. 좌표를 모델이 만들지 않는다.
  반경은 사용자가 고른 참고 조회 거리이며 위험 반경이 아니다.
- 검색 도구는 단일 원문 장소·역할·인용한 상위 지역을 받는다. 검색어는 서버가 이 값으로
  구성한다. 후보에는 검색 당시 역할과 원문 지역/후보 주소의 문자 일치 여부를 보존한다.
  대피 목적지/참고 장소, 상위 지역 미상, 원문 지역과 주소가 다른 후보의 시설 조회는 보류한다.
  이는 행정구역 경계·발생 지점 확인이 아니며 모든 후보는 여전히 미확정이다.
- 모든 결과는 검토 전 자료다. 동명 지점·행정구역 대표점·도로 구간의 점 검색은
  영향 범위를 확정하지 못한다. 주변 시설 0건을 안전으로 표현하지 않는다.
- 원문 인용은 입력의 부분 문자열인지 서버에서 검사한다. 의미 해석 정확성까지
  보증하는 검사는 아니므로 실제 모델 평가와 사람이 읽는 검토가 필요하다.
- 공개 재난문자만 입력하도록 안내한다. 입력 문자는 OpenAI로, 검색어는 Kakao로
  전송된다. 담당자 연락처·시설 메타데이터는 도구 응답에 포함하지 않는다.
- API 키는 서버 환경변수로만 읽고 브라우저·Git에 넣지 않는다.
  Responses `store:false`는 서비스 제공자의 모든 보관 정책을 해제하는 설정이 아니다.
- 모델 호출 최대 6회, 호출당 출력 4,000토큰(추론 토큰 포함), reasoning low, 전체 처리 예산 80초,
  프로세스당 동시 1건·시작 간격 20초·시간당 20건으로 제한한다.
  인스턴스가 늘면 한도가 합산되므로 운영 전 프로젝트 사용량도 확인한다.

## 클라우드 작업에서의 실제 모델 평가

사용자는 2026-11-08 KST OpenAI 크레딧을 충전하고 저장소 Actions secret
`OPENAI_API_KEY`, `KAKAO_REST_API_KEY` 등록을 알렸다. 두 API의 실제 연결을 검증했다.
이 비밀값을 현재 Codex 작업공간으로 꺼내 오지 않는다.
클라우드 파일 미리보기는 사용자 PC의 편집기가 아니다. 아래 로컬 `.env` 안내를
사용자에게 클라우드 파일 편집 방법으로 안내하지 않는다.

`.github/workflows/evaluate-disaster-messages.yml`은 운영 배포와 독립된 평가다.
유료 호출은 수동 요청 때만 실행하며 push나 일반 PR 생성으로 시작하지 않는다.

- main 반영 전: 같은 저장소의 검토용 PR에 `ai-evaluation` 라벨을 붙이면 6개 예문을
  평가한다. 재실행은 라벨을 제거한 뒤 다시 붙인다. fork PR에는 키를 제공하지 않는다.
- main 반영 후: Actions → Evaluate disaster message AI → Run workflow에서
  전체 또는 특정 예문을 고를 수 있다. `with_places`는 기본 false다.
- 현재 기능 브랜치도 API/CLI 수동 실행이 가능함을 확인했다.
  `gh workflow run 410682737 --repo parkgogon/sfety_map --ref feature/disaster-message-ai -f case=partial_release`
  처럼 특정 예문만 재평가할 수 있다. 실제 장소 검색은 `-f with_places=true`를 추가한다.
- 기본 실행은 실제 OpenAI + 장소 검색 미설정 상태다. 위치 미확인/질문 보류를
  검토할 수 있지만 실제 장소·시설 조회 품질은 검증하지 못한다.
- 실제 장소 검색 평가는 별도 secret `KAKAO_REST_API_KEY` 등록 후 PR에
  `ai-evaluation-with-places` 라벨을 붙이거나 수동 실행에서 `with_places`를 켠다.
  키가 없으면 호출을 시작하지 않는다.
- 서버의 호출 상한을 유지하며 최대 6개 예문 × 모델 응답 6회다. 시작 간격 20초,
  동시 실행 1개, 워크플로 제한 15분이다. 인증/모델/요청 형식/통신 오류는 배치를 중단한다.
- 실행 Summary에 점검 결과·API 요청·입출력 토큰·시간을 기록한다.
  `disaster-message-ai-results` 아티팩트의 `results.json`에는 근거·질문·조회 과정이
  있다. 원본 API 응답/키는 기록하지 않으며 보고서는 7일 보관한다.
- 점검 항목이 맞아도 사람이 의미를 검토한다. 사용량은 토큰 단위로 기록하며
  실제 결제액은 OpenAI Usage에서 대조한다. 작은 예문 평가를 일반 정확도로 과장하지 않는다.

일반 자동 테스트는 계속 외부 HTTP/TCP 차단 실행기로만 돌린다.
실제 API 평가는 명시적 `--live`가 필요한 별도 스크립트다.

## 로컬 개발자가 직접 실행할 때

저장소 루트의 `.env.example`을 `.env`로 복사하고 로컬 편집기로
`ADMIN_ACCESS_PASSWORD`, `OPENAI_API_KEY`를 입력한다. 값은 채팅에 보내지 않는다.
장소 검색까지 시연하려면 `KAKAO_REST_API_KEY`도 필요하다.
`OPENAI_MODEL` 기본값은 `gpt-5.4-mini-2026-03-17`이다.

```bash
.venv/bin/uvicorn safety_dashboard.api.app:app --env-file .env --host 127.0.0.1 --port 8080
# 다른 터미널에서
cd field_web
npm run dev
```

`http://localhost:5173/control/messages`에서 관리자 로그인 후 예문을 선택한다.
운영 Cloud Run 연결은 이후 별도 배포 작업에서 Secret Manager로 설정한다.
키가 없어도 화면·오류 처리·도구 연쇄는 가짜 제공자로 검증할 수 있다.

## 검증과 현재 상태 (2026-11-08 KST)

Python 313개·React 220개, 시설 195개, compileall, 웹 빌드 통과.
일반 Python 자동 테스트는 공통 실행기로 실제 외부 HTTP/TCP 시도 0건을 확인했다.
인용·후보/역할/지역·이름/종류·반경 계산·한도·인증·오류 격리·해제 시각과
선택한 대표 후보의 참고 조회 완료를 검증한다.

실제 OpenAI·Kakao 평가의 원본과 보완 내역은 [증빙](evidence/2026-11-08/disaster-message-ai/README.md)에 있다.
최종 실제 API 소스는 `6c81ca1`, 원본 실행은 `42422104880`이다. 이 실행은
입력 검증 거절을 공급자 장애로 잘못 집계한 평가 코드 때문에 실패 상태로 남는다.
모델이 인자를 고쳐 실제 검색은 성공했다. 공급자 장애와 로컬 입력 거절을 구분해
동일한 실제 응답을 재평가했고 6종 지정 점검을 통과했다. 추가 유료 호출/AI 출력 수정은
없다. 실제 공급자 장애·필요한 검색/시설 조회 누락은 계속 점검 실패로 처리한다.

| 창작 예문 | 최종 실제 응답 확인 |
| --- | --- |
| 예방 안내 | 사고로 분류하지 않고 불필요한 조회 생략 |
| 사고 발생 | 산업단지 이름/종류 일치, 3km 참고 시설 7개소, 실제 공장 지점은 미상 |
| 내일 통제 | 발행일 다음 날 09~12시, 주차장 후보 분리·대표점 조회 0개소, 입구 확인 질문 |
| 일부만 해제 | 가람교 해제 ends_at=15:00, 푸른교 통제 유지 분리 |
| 위치 모호 | 중앙동의 시·군 확인 질문, 임의 도시로 시설 조회하지 않음 |
| 사고지와 대피소 | 와룡산(산)·성서초등학교(학교) 구분, 산 주변 1개소만 조회 |

세 참고 조회는 CSV를 별도로 재계산해 ID·거리 일치를 확인했다.
최종 실제 응답을 로컬 브라우저에서 다시 전달한 6종×1440/390/360px 검수도 통과했다.
이는 저장된 실제 응답의 재생이며 새 API 호출/운영 배포 검수가 아니다.
창작 예문 결과를 일반 정확도·현장 대응 성과로 확대하지 않는다.

다음 단계는 사용자와 시연 결과를 검토하고 운영 연결 범위를 결정하는 것이다.
GitHub 키 등록/예문 검증은 완료했다. 운영 Cloud Run 비밀값 연결·main 반영·배포는
아직 하지 않았다. 자동 수집·중복/정정·검토 이력 저장과 사용자 지점 확정은 후속 설계다.


## 후속 업무 흐름 구체화

사용자의 요청에 따라 [문자 분석 이후 업무 흐름 설계안](DISASTER_MESSAGE_WORKFLOW_PLAN.md)을 작성했다.
원문/수신지역을 보존한 문자 등록과 조회, 지도 기준점 확인, 업무 대상 시설 선정,
검토 결과/안내 초안, 후속 문자 연결의 4단계 제안이다. 1·2단계 문자 등록/지역 정보/저장과 지도 기준점/시설 선정을 구현하고 로컬 검증을 완료했다. 운영 배포는 하지 않았다.
