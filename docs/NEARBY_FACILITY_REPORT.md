# 기준점 주변 시설 현황 보고서

기능 브랜치 구현·통합 검증 완료, **운영 미배포**(2026-10-25 KST).
현장·중앙관제의 주변 시설 패널에서 확정 기준점으로 생성한다. 후보 위치에서는 생성하지 않는다.
기본 5km, 빠른 1/3/5km, 직접 0.1~50km(0.1km 단위)를 제공한다. 보고서 반경은 지도 참고 원,
필터·전파 선택·특보/기상 상태와 독립이다. 사건명·상황 시각·메모 입력은 추가하지 않았다.

## API와 계산

기존 `POST /api/v1/reports/nearby.pdf`의 JSON 입력을 유지한다.

```json
{"latitude":35.8714,"longitude":128.6014,"label":"검수 기준점","address":"대구 중구","radius_km":5}
```

이름 1~80자, 주소 최대 250자, 유효 좌표, 반경 범위·단위를 검증한다. 임의 시설 ID 등 추가 필드는
422로 거절한다. 서버 CSV를 매 요청 읽고 지도와 같은 Haversine(지구 반경 6371008.8m)으로 다시 계산한다.
반올림 전 `거리 <= 반경`을 포함하고 거리·시설 ID 순으로 정렬한다. 같은 이름/좌표도 ID별로 보존한다.
기상 조회·전파·서버 영구 저장 없이 인증 전 생성할 수 있다. 기존 기상 보고서의 STALE/ERROR 차단은 유지한다.

성공은 `application/pdf`, `Cache-Control: no-store`, 첨부 파일명과 다음 헤더를 반환한다.

| 헤더 | 의미 |
|---|---|
| `X-Nearby-Facility-Count` | 서버에서 재계산한 시설 수 |
| `X-Nearby-Facility-Digest` | 정렬한 시설 ID 배열의 SHA-256, 기존 계약 유지 |
| `X-Nearby-Map-Status` | 추가 헤더: `captured` / `unavailable` / `busy` / `timeout` |

화면의 대상 수·ID 구성과 다르면 다운로드를 막고 새로고침을 안내한다. 지도 실패는 목록·집계를 유지한
정상 PDF이며 화면에도 지도 누락을 알린다. 시설 조회 실패·빈/잘못된 명부는 503이며 정상 0개소로 바꾸지 않는다.
보고서 처리 슬롯 부족은 429(`Retry-After: 3`), 전체 생성 제한 40초 초과는 504, PDF 계산 오류는 500이다.

## PDF와 지도

기존 한글 폰트·남색/청록·A4 세로를 사용한다. 기준점 이름/주소/좌표, KST 생성 시각, 반경과 한 줄 요약,
시설 수·최근접 거리·유형 수·담당부서 수 카드, 큰 위치도, 가까운 시설 TOP5, 거리대·유형·부서 분석,
거리순 전체 목록을 담는다. 5개소 이하는 TOP5와 전체 목록을 합치고 분량이 맞으면 분석도 같은 쪽에 배치한다.
0개소도 정상 보고서다. 긴 한글·긴 행과 많은 시설은 머리말·번호를 유지하며 다음 쪽으로 이어간다.

지도는 실제 Kakao SDK의 도로·지명 위에 기준점·선택 반경·시설 번호·북쪽을 표시하고 Chromium 자체
캡처로 한 장만 만든다. 카카오 로고·축척을 유지하며 타일 병합·CORS 헤더 변경을 하지 않는다.
밀집 번호를 묶어도 실제 시설 좌표는 점으로 보존하고 이동한 번호는 안내선으로 연결한다.
지도와 목록의 ID·좌표·반경·집계·번호 그룹 및 이미지 SHA-256을 대조한다.
지도 비활성·실패·사용 중·시간 초과에는 **지도 생성 실패**와 이유를 표시하고 시설 목록/집계를 제공한다.

유형은 CSV 원문 유형(앱의 7개 그룹과 다를 수 있음), 부서는 등록 부서별로 집계한다.
거리대는 1/3/5km와 선택 반경의 오름차순 경계이며 0m를 포함하고 경계 시설은 한 번만 센다.
목록은 시설명·유형·직선거리·주소·담당부서를 담고 전화번호·담당자 원문은 제외한다.
가까운 시설을 피해·고위험 시설로 표현하지 않으며 실제 피해 여부와 별개라는 안내를 유지한다.

## 요청 수명과 자원 제한

- 인스턴스당 지도 캡처 1건, 보고서 처리 3건, PDF 계산 1건이다. 캡처 슬롯 사용 중에는 기다리지 않고 지도 실패 PDF로 진행한다.
- 지도 캡처 기본 제한 20초(설정 5~30초), PDF 계산 슬롯 대기 10초, API 전체 제한 40초, 웹 요청 제한 45초다.
- 중복 클릭을 막고 닫기·바깥 클릭·Escape·화면 종료 시 요청·다운로드를 취소한다. ASGI 연결 종료를 감지해 브라우저를 닫는다.
- PDF 계산 슬롯 대기는 취소할 수 있다. 대기 중 닫힌 요청은 계산을 시작하지 않고 요청 슬롯을 반환한다.
- 이미 실행 중인 PDF 스레드는 강제 중단하지 않는다. 계산 종료·슬롯 반환을 기다린 뒤 요청 정리를 끝낸다.
- 매 요청 새 Chromium/context를 사용하고 종료한다. API 이미지의 `tini`가 브라우저 보조 프로세스도 회수한다.
- 기준점·보고서·캡처는 요청 메모리에서만 사용한다. 저장·자동 전파하지 않는다.

기본 캡처 플래그는 꺼져 있다. 향후 배포 설정은 API 1 CPU/1GiB, 기존 동시 요청 40/최대 인스턴스 3을
유지하므로 전체 서비스의 동시 캡처를 1건으로 보장하는 방식은 아니다. Worker 이미지는 브라우저를 포함하지 않는다.
