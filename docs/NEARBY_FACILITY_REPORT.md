# 기준점 주변 시설 현황 보고서

기능 브랜치에서 구현했다. 운영 배포는 하지 않았다.

현장·중앙관제의 주변 시설 패널에서 확정 기준점으로 생성한다. 후보 위치에서는 생성하지 않는다.
기본 5km, 빠른 1/3/5km, 직접 0.1~50km(0.1km 단위)를 제공한다. 반경은 생성창 안의 상태이며
지도 1·3·5km 참고 원, 필터, 전파 대상, 특보/기상 상태와 독립이다.
기준점·반경·대상 수와 거리순 전체 목록을 확인하고 PDF를 다운로드한다.

## API와 계산

`POST /api/v1/reports/nearby.pdf`, JSON:

```json
{"latitude":35.8714,"longitude":128.6014,"label":"검수 기준점","address":"대구 중구","radius_km":5}
```

이름 1~80자, 주소 최대 250자, 유효 좌표, 반경 범위·단위를 검증한다. 임의 시설 ID 등 추가 필드는
422로 거절한다. 인증 없이 생성하며 기상 조회·전파·외부 지도 서비스·서버 저장은 하지 않는다.
서버 `facilities_info.csv`를 매 요청 읽고 지도와 같은 Haversine(지구 반경 6371008.8m)으로 계산한다.
반올림 전 `거리 <= 반경`을 포함하고 거리·시설 ID 순으로 정렬한다. 같은 이름/좌표도 ID별로 보존한다.
조회 실패·빈 명부·잘못된 명부는 503, PDF 오류는 500이며 정상 0개소와 구분한다.

성공은 `application/pdf`, `Cache-Control: no-store`, 첨부 파일명과 `X-Nearby-Facility-Count`, 대상 ID 목록의 SHA-256 `X-Nearby-Facility-Digest`를 반환한다.
화면의 대상 수·ID 구성과 서버 결과가 다르면 다운로드를 막고 새로고침을 안내한다. 대상과 기준점은 서버에 보관하지 않는다.
생성 중 중복 클릭을 막고 닫기·바깥 클릭·Escape·화면 종료 시 AbortController로 요청과 다운로드를 취소한다.
이미 시작한 서버의 메모리 내 PDF 계산까지 중단됨을 보장하는 기능은 아니다.

## PDF

기존 한글 폰트·남색/청록·A4 세로를 사용한다. 기준점 이름/주소/좌표, 생성 시각 KST, 반경,
전체 명부 수·대상 수·유형별 수, 북쪽·축척·반경과 위치도 번호, 거리순 전체 목록을 담는다.
위치도는 방위정거 개략도이며 도로 지도는 아니다. 밀집 시설은 같은 번호로 묶고 목록의 번호와 연결한다.
목록은 시설명·유형·직선거리·주소·담당부서를 표시한다. 긴 한글/긴 행과 많은 시설은 페이지를 나누고
표 머리말·위치도 번호를 이어 표시한다. 전화번호·담당자 원문은 담지 않는다.
0개소도 정상 PDF다. 반경 안의 위치가 실제 피해·영향 판정이 아니라는 안내를 유지한다.

검증과 한계: [직접 검토 증빙](evidence/2026-10-25/nearby/README.md).

## 지도 배경에 대한 추가 의견 — 2026-10-25

사용자는 도로·지명이 없는 위치도가 너무 단순하다고 지적했다. 현재 PDF는 배경 없이 기준점·거리 원·시설 번호를
그리는 개략도다. 실제 도로 지도가 누락된 오류나 환경 차단 때문에 백지가 된 것이 아니다.
사건 주변을 파악하는 보고용에는 도로·지명 위에 기준점·반경·시설 번호를 겹치는 형태가 더 적합하다.
이 지도 배경 개선은 아직 구현하지 않았다. 기존 시설 계산·보고서 목록은 그대로 유효하다.

현재 Kakao SDK를 캡처해 PDF에 넣는 방법은 바로 채택하지 않는다.
2026-10-19 [카카오 공식 답변](https://devtalk.kakao.com/t/api-saas/152207)은 API로 만든 지도 이미지의
다운로드·서버 저장 활용을 허용하지 않는다고 안내한다. 일반 화면 검수용 캡처와 제품의 자동 PDF 기능을 구분한다.
다음 검토는 PDF 출력이 가능한 지도 자료/공급원과 국내 도로·지명 품질을 확인한 뒤,
실제 배경 지도·기준점·반경·시설 번호가 보이는 보고서 시안을 만드는 것이다. 아직 공급원·요금·키는 정하지 않았다.
