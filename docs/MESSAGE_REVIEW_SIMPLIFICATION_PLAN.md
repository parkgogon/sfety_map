  자동 수집 → AI 준비 → 사람의 한 화면 검토로 업무를 줄인다.

## 1. 확인한 현황과 목표

현재 공식 피드 키는 미연결이고 `OfficialFeedService`는 사람이 지역/하루/페이지를 조회·선택 등록하는 서비스다.
공식 키를 넣는 것만으로 자동 수집이 시작되지는 않는다.
`MessageSpatialService`는 기준점 확인과 시설 선정을 따로 저장하며,
`MessageReviewService`는 그 확인 기록이 있어야 완료/초안을 만든다.
따라서 화면만 접거나 여러 버튼을 순서대로 대신 누르는 방식으로는 업무가 충분히 줄지 않는다.

사용 목적은 **우리 소관시설에서 확인할 상황과 전달할 안내 문구를 빠르게 준비하는 것**이다.
정상적인 한 건은 목록에서 열기 → 내용 확인 → `이 내용으로 검토 완료`로 마친다.
목표는 목록 진입 이후 주요 버튼 조작 2회이며, 필요한 안내문 복사는 별도 1회다.
위치/시각/대상 판단에 필수 정보가 부족한 건은 필요한 질문만 추가한다.
내부 검토 완료·시설 추천·원문에서 언급한 실제 현장 상태는 서로 구분한다.

## 2. 사용자가 보는 기본 화면

### 입구

- 첫 화면에서 `공식 문자 자동 수집 미연결 / 수집 중 / 조회 지연·오류`와 마지막 정상 조회 시각을 표시한다.
  공식 API에 공개된 문자를 주기적으로 가져오는 방식임을 설명한다.
- 기본은 검토 대기함이다. 화면용 분류는 `검토 대기 / 확인 필요 / 완료`를 중심으로 한다.
  분석 대기/분석 중/실패는 각 카드에 표시하고, 실패를 새로운 문자가 없다는 뜻으로 표현하지 않는다.
- 수동 붙여넣기와 창작 시연은 보조 진입점으로 두며 출처를 구별한다.
  자동 수집이 연결되기 전에도 그 상태와 지금 가능한 입력 방법을 명시한다.

### 한 건의 상세

다음 네 항목을 한 화면에 순서대로 제시한다. 모바일에서는 같은 순서로 짧게 내려 읽는다.

1. 무슨 상황인지: 원문 출처/지역/발행 시각과 짧은 요약. 원문 전체는 펼쳐서 확인한다.
2. 무엇이 불확실한지: 꼭 필요한 확인 사항만 위쪽에 표시한다.
3. 우리 시설 중 어디를 확인할지: 추천 위치가 표시된 지도, 주변 참고 시설/확인 대상 제안과 근거.
4. 전달할 내용: 아직 승인하지 않은 안내 초안 미리보기.

기본 동작은 `이 내용으로 검토 완료`, `내용 수정`, `보류`다.
`내용 수정`에서 위치·조회 거리·시설·추가 안내를 바꾼다. 기본 조회 거리는 현재의 3km를 유지한다.
개별 기준점 저장/시설 저장/완료 사유 입력을 정상 흐름의 필수 단계에서 제거한다.
완료 후 `안내문 복사`를 제공한다. 실제 발송/회신 기능과 구별한다.
검색 과정·좌표 직접 입력·변경 이력·후속 연결 수동 관리는 상세 정보로 이동한다.

## 3. 자동 준비와 사람의 판단

| 항목 | 자동으로 준비할 것 | 사람이 개입할 때 |
| --- | --- | --- |
| 공식 문자 등록 | 원문·공식 ID·발행/수신지역·조회 출처를 보존해 중복/정정 처리 | 공식 원문과 다른 설명은 별도 메모 |
| 수동 입력 | 원문 붙여넣기부터 시작, 출처는 수동 입력으로 표시 | 시간·지역이 판단에 필요하고 원문으로 모를 때만 보완 |
| AI 분석 | 원문에 맞는 도구 선택 → 장소 검색/시설 조회 → 검증된 해석 저장 | 필수 정보가 부족할 때 질문에 답하거나 보류 |
| 지도 | 검증된 장소 후보와 기본 거리로 참고 조회 제안 | 동명 장소·광역 대표점·구간 등 판단이 필요하면 선택/수정 |
| 시설 | 실제 CSV 계산으로 주변 참고 시설과 검토 대상 제안 | 제안을 확인하고 필요하면 추가/제외 |
| 안내 초안 | 원문/해석/조회 근거/제안 시설을 바탕으로 확정 전에 미리 작성 | 추가 안내를 수정하거나 그대로 승인 |
| 사유/이력 | 원문 근거·계산 기준·추천 내용·사용자 변경 내역 기록 | 특이한 변경/추가 조치 없음은 간단한 사유 선택, 자유 메모는 보조 |
| 후속 문자 | 관련 가능성이 있는 이전 기록 제안·변경 구간 비교 | 같은 상황인지 확인하고 변경안을 함께 승인 |

AI의 추천안과 사람이 승인한 결과는 별도로 보존한다.
새 추천을 현재의 `confirmed_at`/`selection_saved_at`/`review_completion`에 자동 대입하지 않는다.
추천안을 승인할 때 서버가 현재 원문·분석·시설 자료·후속 근거를 다시 검증하고 한 번에 확정한다.
AI를 승인 버튼 뒤에서 다시 호출하거나, 기존 여러 저장 API를 브라우저에서 연속 호출해 부분 완료를 남기지 않는다.
기존 저장소의 한 문서/버전 트랜잭션과 CAS를 활용한다.

### 위치와 미상 정보 처리

- 단일 후보가 있다는 이유만으로 실제 사고 지점이라고 단정하지 않는다.
  원문 역할·지역·주소/장소 종류·후보 모호성을 함께 확인한다. 모델의 자신감 점수만으로 확정하지 않는다.
- 산업단지/산/도로 구간 대표점은 그 성격과 한계를 표시한다.
  관리자가 대표점 참고 조회로 검토할지, 위치를 보완할지 선택할 수 있게 한다.
- 대피 목적지/단순 참고 장소를 사고 기준점으로 사용하지 않는다.
  주변 시설 수·거리는 피해·위험 범위·현장 확인 실적이 아니다.
- 발행 시각이 없는 수동 문자는 수집/입력 시각과 발행 시각 미상을 구분한다.
  현재 시각을 발행 시각으로 만들어 넣지 않는다. 상대시각 해석이 필요한 경우에만 확인을 요청한다.
  기존 필수 `issued_at` 계약은 미상 지원과 과거 기록 호환을 함께 변경해야 한다.
- 시설 0개소/예방 안내를 안전 판정이나 자동 검토 완료로 처리하지 않는다.
  추가 조치 없음은 관리자의 명시적 선택으로 남긴다.

## 4. 공식 자동 수집·분석

- 별도 SafetyData 키가 필요하다. 기존 OpenAI/Kakao 키로 대체할 수 없다.
  실제 응답·조회 조건·이용/보관 조건 확인 전에는 운영 자동 수집을 켜지 않는다.
- 기본 제안은 소관 5개 광역지역의 5분 주기 조회다. 실제 API 제공 지연/쿼터를 확인해 확정한다.
- 공식 ID와 원문 버전으로 중복 수집/중복 유료 분석을 막는다. 같은 ID의 정정은 새 버전과 재검토로 남긴다.
  같은 본문이어도 서로 다른 공식 ID를 임의로 같은 사건으로 합치지 않는다.
- 기존 수동 UI의 첫 3페이지 상한을 전체 수집 완료 조건으로 재사용하지 않는다.
  정렬/페이지 조건을 확인하고 조회 범위/진행 지점을 저장한다. 겹치는 구간 재조회로 지연 도착/자정 경계를 처리한다.
  한도 도달/누락 가능성/실패는 표시하고 마지막 정상 자료를 보존한다.
- 수집은 브라우저가 닫혀 있어도 지속한다. 기존 KMA 알림 실행 안에 유료 AI 처리를 연결하지 않는다.
  현재 코드베이스/Firestore와 별도 실행 경로를 활용하고 장기 상주 서버를 추가하지 않는다.
- 등록된 새 버전을 분석 대기열로 처리하며 실행권을 중복 확보하지 않도록 한다.
  실행 중 장애/오래된 실행권·재시작·재시도와 관리자 동시 수정/승인 충돌을 처리한다.
- 자동 분석에는 동시 실행·일일 처리 상한을 둔다. 건별 기존 최대 6회/80초 한도를 유지한다.
  초과 건은 대기 상태로 보존하고 수동 분석/재분석도 같은 집계에서 관리한다.
  초기 활성 시 과거 자료를 한꺼번에 유료 분석하지 않도록 시작 범위를 명시한다.
  구체적 일일 상한은 실제 피드 건수/사용량을 확인하고 활성화 설정에 포함한다.
- 단순 기상 표현이 있다는 이유로 원문을 버리지 않는다. 기상 안내에 섞인 하천/도로 통제 등 비정형 내용은 유지한다.

## 5. 구현 단계와 수용 조건

| 단계 | 범위 | 끝났다고 볼 조건/검증 |
| --- | --- | --- |
| 1. 수동/창작 경로 간소화 | 입력 입구·추천안/초안 미리보기·한 화면 수정/일괄 확정·상세 정보 접기 | 명확한 1건을 등록/분석 후 개별 기준점/시설 저장·사유 타이핑 없이 완료. 추천/승인 분리·원자적 확정·중복 클릭·CAS·근거 변경/미상 시각·과거 기록 호환 테스트. PC/390/360px에서 실제 짧은 동선 확인 |
| 2. 공식 자동 수집/분석 | 지속 수집·ID/버전 중복 방지·수집 상태·분석 대기열/상한 | 브라우저를 닫아도 새 문자가 검토 대기로 준비됨. 자정/페이지 경계·정정·지연 도착·실패·재시작·동시 실행·상한 초과를 가짜 제공자로 검증. 실제 키 연결 후 제한된 운영 응답 대조 |
| 3. 후속 변화/예외 정리 | 관련 기록 제안·변경 구간·필요 질문만 표시·한 번의 변경 검토 | 같은 표기만으로 사건을 합치지 않음. 일부 해제와 통제 유지를 보존하고 오래된 초안/완료를 차단. 후속 변경도 매번 수동 연결 메뉴를 찾지 않고 검토 가능. 불명확/0시설/추가 조치 없음/재분석 실패 검증 |
| 4. 시연/운영 전환 검수 | 이해하기 쉬운 기본 화면과 실제 업무 시나리오·배포 준비 | 명확한 사고/대표점 모호/일반 안내/부분 해제/자료 오류를 휴대폰 흐름으로 대조. 기존 기록·KMA/알림 회귀 검사, 비용/수집 상태·복구 기준 확인. 실제 기관 전달은 기존 방식으로 하며 시험 발송 없음 |

1단계를 먼저 완성하면 공식 키 준비와 관계없이 바로 짧아진 사용 흐름을 검토할 수 있다.
각 단계는 독립 검증 후 다음 단계로 진행한다. 필요한 실제 API/유료 검수는 허용 범위와 상한을 정해 제한한다.
자동 테스트는 기존 외부 HTTP/TCP 차단 실행기와 가짜 제공자를 사용한다.
일괄 확정·자동 수집/비용·근거 무효화가 주요 회귀 검사 대상이다.

## 6. 이번 범위와 보류

- 기존 원문/분석/선정/완료/초안/이력과 사용자가 등록한 기록은 보존한다.
  기존 확정 기록을 새 추천안으로 덮거나 자동 재분석하지 않는다.
- 자동 수집/분석은 운영 기능으로 추가하지만, 실제 전파/담당자 연락·현장 회신은 이번 간소화에 포함하지 않는다.
  관리자는 확정된 대상/문구를 복사해 기존 보고·전달에 사용한다.
- 기존 KMA 위험도/알림 기준 상태·dispatch·Worker 시험 경로는 건드리지 않는다.
  내부 검토 완료를 재난 종료·시설 안전 확인·발송 실적으로 표현하지 않는다.
- 이번 요청은 계획 정리까지다. 앱 코드·키·운영 설정·배포는 변경하지 않았다.
  다음 구현 시작점은 **1단계 수동/창작 경로의 추천안과 한 번의 검토 완료**다.
