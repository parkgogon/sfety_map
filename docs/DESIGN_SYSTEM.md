# K-ECO Safety Monitoring 디자인 시스템

> 상태: **확정**
> 적용 범위: 시설담당자용 현장 지도, 중앙 관제, 설정, Telegram·PDF 작업창

이 문서는 React 현장 지도와 Streamlit 중앙 관제가 같은 제품으로
보이고 동일하게 동작하도록 하는 표현 기준이다. 새 화면을 만들 때는
개별 페이지의 선호보다 이 문서와 `safety_dashboard/ui/design_tokens.css`를
우선한다.

## 1. 제품 표현 원칙

전체 콘셉트는 **차분한 공공안전 관제**다.

- 평상시에는 조용하고 정돈된 화면을 제공한다.
- 빨간색과 주황색은 위험 상태에만 사용한다.
- 상태·판정 근거·권장 행동을 장식보다 먼저 표시한다.
- 정상 상태는 작게, 오류·지연·임시 정책은 명확하게 표시한다.
- `영향 없음`을 `안전` 또는 `정상`으로 바꾸어 표현하지 않는다.
- 색상만으로 상태를 구분하지 않고 항상 등급 문구를 함께 표시한다.

## 2. 디자인 토큰

토큰의 단일 기준은 `safety_dashboard/ui/design_tokens.css`다. Streamlit은
`app.py`에서 이 파일을 먼저 읽고 화면별 `style.css`를 나중에 읽는다. React
현장 지도를 추가할 때도 같은 토큰 파일을 빌드 입력으로 사용하고 색상과
간격을 다시 정의하지 않는다.

### 주요 토큰 그룹

- 브랜드·텍스트: `--color-brand-*`, `--color-text-*`
- 배경·표면·테두리: `--color-bg-*`, `--color-border`
- 위험도: `--color-risk-*`
- 운영 상태: `--color-status-*`
- 간격: `--space-1`~`--space-6`
- 모서리·그림자: `--radius-*`, `--shadow-card`
- 레이아웃·터치: `--layout-max-width`, `--touch-target-min`

위험도 색상은 `risk_policy.toml`, PDF, Python 지도 렌더러와 같은 값을 사용한다.
색상을 바꿀 때는 CSS만 바꾸지 말고 보고서·지도·정책 표현을 함께 회귀 검사한다.
자동 판정이 불가능한 `미판정`은 보라색, KMA 자료 자체를 받지 못한
`조회 불가`는 회색으로 구분한다.

| 표시 | 색상 | 용도 |
| --- | --- | --- |
| 상 | `#D92D20` | 즉시 확인이 필요한 높은 위험 |
| 중 | `#C2410C` | 주의 깊은 확인이 필요한 위험 |
| 하 | `#8A6D00` | 특보 영향권의 관찰 대상 |
| 영향 없음 | `#176B87` | 특보의 영향권에 들지 않음 |
| 미판정 | `#7C3AED` | 기준 미등록 특보로 위험등급 판정불가 |
| 조회 불가 | `#667085` | 기상청 데이터 미수신으로 위험등급 판정불가 |

화면 범례는 `상 → 중 → 하 → 영향 없음 → 미판정 → 조회 불가` 순서로
표시한다. 이 순서는 가독성을 위한 것이며 클러스터 대표 시설과 중앙 관제의
위험 우선순위 계산에는 사용하지 않는다. `영향 없음`은 절대적인 안전을
뜻하지 않는다.

## 3. 타이포그래피와 간격

- 기본 글꼴은 Pretendard, Noto Sans KR, OS 시스템 글꼴 순서를 사용한다.
- 모바일 본문은 15px 이상, 관리자 표는 13~14px을 기본으로 한다.
- 모든 간격은 4px 기반 토큰을 조합한다.
- 모바일 터치 대상은 최소 44×44px을 유지한다.
- 긴 영문 대문자 브랜드 문구는 작게 표시하고 페이지 제목보다 강하게 표시하지 않는다.

## 4. 역할별 화면 구성

### 시설담당자 현장 지도

모바일 지도 앱처럼 `작은 상태 표시 → 검색·필터 → 큰 지도 → 선택 시설
하단 시트`로 구성한다.

- 고정 담당시설 묶음을 만들지 않고 사용자가 그때그때 시설을 검색하거나 선택한다.
- 검색창은 항상 표시하고 시설 유형·지역·위험도는 `필터`에 숨긴다.
- 적용된 필터만 작은 태그로 표시한다.
- 지도는 위험 시설을 강조하고 영향 없는 시설은 작고 옆게 표시한다.
- 마커와 하단 시트는 `facility_id`로 동기화한다.
- 접힌 시트는 등급·시설명·핵심 특보·권장 행동만 표시한다.
- 현재 기상·재난문자·CCTV·뉴스는 사용자가 현장정보를 요청할 때 조회한다.
- Telegram·PDF·위험도 설정은 현장 지도에 표시하지 않는다.

### 중앙 관제

데스크톱 업무 흐름은 `조회 범위 → KPI → 지도·우선순위 → 대상 확정 →
Telegram 또는 PDF`를 유지한다.

- KPI는 숫자와 짧은 설명만 표시한다.
- 지도와 우선순위는 데스크톱에서 2열로 배치한다.
- 대상 표는 전체 너비를 사용하고 위험도는 왼쪽 선과 배지로 표시한다.
- 발송과 보고서 작업은 동일한 확정 대상을 사용한다.
- 실제 발송은 미리보기·대상 수·확인 체크 후에만 가능하다.

### 설정

- 위험도 정책 버전과 임시 적용 여부를 상단에 표시한다.
- 정책 표는 활성 특보를 상단에 우선 표시하되 강한 전체 행 배경을 쓰지 않는다.
- 임시 기준은 현재 브라우저 세션에만 적용한다.
- API 키·시설 CSV·사용자 관리를 위험도 편집 화면에 섞지 않는다.

## 5. 공통 컴포넌트

- **상태 표시**: 정상은 작은 한 줄, 오류·지연은 독립 배너로 표시한다.
- **위험도 배지**: 색상과 등급 텍스트를 함께 표시한다.
- **카드**: 흰색 표면, 1px 테두리, 절제된 그림자를 사용한다.
- **필터**: 모바일은 하단 시트, 데스크톱은 팁오버를 기본으로 한다.
- **버튼**: 핵심 작업만 강한 색상을 쓰고 초기화·취소는 보조 표현을 쓴다.
- **표**: 위험 행 전체를 고채도로 칠하지 않고 헤더·왼쪽 선·배지로 구분한다.
- **작업창**: 제목 → 범위 → 미리보기 → 주의사항 → 취소·확정 순서를 유지한다.

## 6. 지도 표현

- 시설담당자용 React 현장 지도는 **카카오맵 Web API**를 사용한다.
- 카카오 JavaScript 키는 허용된 로컬·테스트·운영 도메인에만 등록한다.
- 배경 지도는 기본 카카오맵을 사용하고 별도의 고채도 스타일을 덧씌우지 않는다.
- 원거리에서는 시설을 클러스터로 묶고 확대 후 개별 마커를 표시한다.
- 시설 전체 범위 맞춤은 최초 진입 때만 수행하고 필터·상세·자료 모드 변경은 현재 지도 위치를 유지한다.
- 영향 시설을 크기와 색으로 강조하고 영향 없는 시설은 작고 옆게 표시한다.
- 선택 시설은 남색 이중 테두리로 강조한다.
- 특보 경계는 10~15% 정도의 낮은 투명도로 표시한다.
- 기상 격자는 기본으로 끄고 강수·바람·기온 중 하나만 표시한다.
- 기상 색상은 `--color-weather-*` 토큰을 사용하고 위험등급 색상과
  섞어 사용하지 않는다.
- CCTV는 위험도와 혼동되지 않는 카메라 아이콘을 사용한다.
- 위험등급 범례는 기본 펼침으로 시작하되 사용자가 작은 pill로 접을 수 있다.
- 기상 레이어는 기본으로 끄고 사용자가 요청할 때만 불러온다.

## 7. 반응형·접근성

- 700px 이하는 모바일, 그 이상은 데스크톱 기본 구성을 사용한다.
- 모바일과 데스크톱은 크기만 줄이지 말고 정보 배치를 다르게 한다.
- 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 키보드 포커스를 숨기지 않고, 모든 아이콘 버튼에 접근 가능한 이름을 제공한다.
- 색상, 도형, 텍스트를 함께 사용해 상태를 전달한다.
- 지도를 사용하지 못하는 경우를 위한 검색·목록 경로를 유지한다.

## 8. 데이터 상태 표현

- **로딩**: 기존 정보를 유지하고 `새 자료 확인 중`을 작게 표시한다.
- **지연**: 기존 자료의 기준 시각과 갱신 실패를 함께 표시한다.
- **자료 없음**: 결과가 없음을 알리되 안전을 의미하지 않음을 명시한다.
- **오류**: 실패한 외부 정보 영역만 오류로 표시하고 핵심 관제 기능을 막지 않는다.
- **모의훈련·임시 정책**: 실시간과 혼동되지 않도록 전용 배지를 사용한다.

## 9. 금지 규칙

- 위험색을 일반 제목·네비게이션·발송 버튼 장식으로 사용하지 않는다.
- 같은 수치나 설명을 지도·카드·표에 반복하지 않는다.
- 긴 사용법·정책 버전·개발자 설정을 핵심 화면에 상시 노출하지 않는다.
- 데스크톱 표를 모바일에 그대로 축소하지 않는다.
- 화면 전체를 스피너로 덮거나 갱신 중 기존 자료를 지우지 않는다.
- 아이콘만으로 위험도·작업·오류를 설명하지 않는다.

## 10. 변경 체크리스트

화면을 추가하거나 수정할 때 다음을 확인한다.

- 기존 토큰으로 표현했는가?
- 위험색이 실제 위험과 경고에만 쓰였는가?
- 모바일 터치 크기와 텍스트 대비를 확인했는가?
- 로딩·빈 결과·지연·오류 상태가 구분되는가?
- 데스크톱·390px 모바일에서 둘 다 검증했는가?
- 현장 지도에 관리자 작업이, 중앙 관제에 현장 참고정보가 불필요하게 노출되지
  않았는가?
