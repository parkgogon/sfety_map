## 1. 목표

현장 안전지도에서만 자연스럽게 진입할 수 있는 모의훈련을 현장지도,
중앙관제, PDF, 수동 상황전파에서 같은 모드와 같은 관제 snapshot으로
사용하도록 통합한다. 모의훈련 지도의 기상 그래픽은 고정 훈련 특보와
연관된 가정값을 표시하되 실제 관측과 명확히 구분한다.

## 2. 현재 사실

- 공개 관제 API는 `mode=simulation`을 지원하고 고정 특보 4건을 반환한다.
- 중앙관제도 `/control?mode=simulation`으로 직접 접속하면 훈련 snapshot을
  읽지만, 화면에 모드 전환·종료 UI가 없다.
- 현장지도에서 `navigate("/control")`로 이동하면 `mode=simulation`이
  사라져 실시간으로 돌아간다.
- PDF와 수동 Telegram은 중앙관제가 훈련 모드인 경우 이미 훈련
  표식·분류·이중 확인을 지원한다.
- 자동알림 Worker는 `simulation=False`만 사용하며 이 격리는 유지해야 한다.
- 기상 레이어 API와 React hook은 모드를 받지 않아 훈련 중에도 실제
  KMA 실황만 표시한다.
- 2026-08-29 운영 훈련 API 확인값은 `SIMULATION`, 특보 4건, 영향시설
  31개소, 상 위험 10개소였다.

## 3. 확정 방향

1. 훈련 상태는 URL의 `mode=simulation`을 단일 기준으로 삼는다.
2. 훈련 모드를 localStorage에 영구 저장하지 않는다. 새 접속은 항상
   실시간이 기본이다.
3. 현장지도·중앙관제 이동 시 `mode` 쿼리를 보존한다.
4. 두 화면에 같은 모의훈련 배너와 `실시간으로 돌아가기`를 두고,
   중앙관제에도 발견 가능한 `모의훈련 시작` 진입점을 둔다.
5. 선택 시설의 `실제 현재 기상`은 실황 참고정보로 유지하고, 훈련
   위험도·가정값과 섞지 않는다.
6. 지도 기상 그래픽만 훈련 특보와 일치하는 결정적 가정값으로
   생성하고 `실제 관측이 아님`을 명시한다.
7. 모의훈련은 자동알림 기준 상태, 실전 중복 방지, 실전 실적을 절대
   변경하지 않는다.

## 4. 구현 순서

### 4.1 공통 모드·라우팅

- `field_web/src/router.ts`, `utils.ts`에 모드 쿼리 생성·보존 helper를 둔다.
- `App.tsx`, `ControlApp.tsx`가 공통 `useMonitoringMode` 또는 동일 계약을
  사용하게 한다.
- 중앙관제의 현재 미사용 `setMonitoringMode`를 실제 전환 UI에 연결한다.
- 공통 `SimulationBanner` 컴포넌트를 두 화면에서 사용한다.
- 중앙관제의 자동감시·운영 지표는 `실제 운영 참고`로 표시해
  훈련 KPI와 섞여 보이지 않게 한다.

### 4.2 훈련 시나리오 단일 정의

- `safety_dashboard/simulation/scenarios.py`를 추가해 시나리오 ID·이름,
  특보, 기상 가정, 추천 레이어를 함께 정의한다.
- `adapters/kma.py` 내 고정 특보를 이 정의에서 생성하게 전환한다.
- 이번 범위는 기존 특보 4건을 사용하는 `multi_hazard_demo`
  하나로 제한한다. 다중 시나리오 선택 UI는 후속 개선이다.

### 4.3 특보 연관 훈련 기상 레이어

- `SimulationWeatherLayerProvider`를 실제 KMA provider와 분리해 추가한다.
- 내장 특보구역 도형의 중심과 관제 권역 격자를 이용한다.
- 난수를 사용하지 않고 중심에서 멀어질수록 부드럽게 감쇠하는
  값을 생성한다.
- 초기 훈련 가정값은 공식 임계치가 아닌 화면 표현용 예시로 사용한다.
  - 안동 태풍 경보: 중심 풍속 20~28m/s, 주변 강수 20~40mm
  - 구미 강풍 주의보: 풍속 12~16m/s
  - 포항 호우 경보: 1시간 강수 30~50mm
  - 대구 폭염 경보: 기온 35~38℃
- 태풍은 회전하는 바람장, 강풍은 일정 방향의 바람으로 구분해
  그린다.

### 4.4 API·캐시 계약

- `GET /api/v1/weather/layers/{layer}`에 `mode=live|simulation`을 추가한다.
- 훈련 응답에 `status=SIMULATION`, `actual_data=false`, `scenario_id`,
  `scenario_label`, `source=모의훈련 시나리오`를 반환한다.
- 실시간 응답은 기존 계약과 외부 KMA 조회를 그대로 유지한다.
- 서버 캐시는 `(mode, scenario_id, layer)`로 분리하고, 실패 시 마지막
  정상 실황 재사용은 live 캐시 내에서만 허용한다.
- 모의훈련 레이어 생성은 외부 KMA API를 호출하지 않는다.

### 4.5 React 지도 통합

- `fetchWeatherLayer`, `useWeatherLayer`에 `monitoringMode`를 전달하고 브라우저
  캐시도 모드별로 분리한다.
- 훈련 진입 시 특보 우선순위로 추천 레이어를 자동 선택한다.
  `태풍·강풍 → 바람`, `호우 → 강수`, `폭염 → 기온` 순서다.
- 현재 종합 시나리오는 태풍이 있으므로 바람을 기본 표시한다.
- 중앙관제 `대상 분석·전파` 지도에도 기상 레이어 선택·범례를
  추가한다.
- 훈련 범례에서 `실황`을 사용하지 않고 `모의훈련 기상 가정`,
  `실제 관측이 아님`을 표시한다.
- 실시간 복귀 시 훈련 레이어를 즉시 제거해 혼재 표시를 막는다.

### 4.6 기존 출력·운영 격리 회귀 확인

- PDF는 전체 페이지 모의훈련 표식을 유지한다.
- 수동 Telegram은 `DRILL` 분류, 훈련 문구, 이중 확인을 유지한다.
- 훈련 진입만으로 메시지를 자동 발송하지 않는다.
- Worker, Firestore 운영 baseline, 중복 방지, live 실적은 변경하지 않는다.
- 훈련 실적은 기존처럼 실전 실적과 구분하고 중앙관제에 훈련
  배지·필터를 표시한다.

한 AI가 전부 한 번에 구현하지 않는다. 아래 단계 하나만 구현·검증한 뒤 다음
단계로 넘어간다. 교체하거나 중단할 때는 이 절의 완료 상태와 `HANDOFF.md`의

   - 완료 기준: 관련 React 테스트와 빌드 통과, 두 화면 이동 시 훈련 mode 유지

   - 완료 기준: 외부 KMA 미호출·결정성·live 격리 Python 테스트 통과
3. **지도 기상 그래픽 연결**

4. **출력·운영 격리 및 최종 검수**

   - 완료 기준: 이 문서의 수용 조건 전부와 `scripts/verify_all.sh` 통과

## 5. 테스트 계획

### Python

- 모의훈련 기상 레이어가 외부 KMA를 호출하지 않는다.
- 호우·강풍·폭염·태풍 지역 근처의 관련 레이어 값이 가정 범위에
  든다.
- 훈련 결과는 동일 입력에 항상 동일하다.
- live·simulation 서버 캐시와 마지막 성공 상태가 섞이지 않는다.
- 레이어 route가 mode를 전달하고 잘못된 mode는 HTTP 422를 반환한다.
- Worker는 계속 `simulation=False`만 사용한다.

### React

- 현장지도 ↔ 중앙관제 이동 시 `mode=simulation`이 유지된다.
- 중앙관제에서 훈련 시작·종료가 가능하다.
- 두 화면이 같은 훈련 배너를 표시한다.
- 훈련 기상 요청이 `mode=simulation`을 포함한다.
- 태풍 포함 시 바람 레이어가 기본 선택된다.
- 훈련 범례는 `실제 관측이 아님`을 표시하고 실시간 복귀 시 사라진다.
- PDF URL·수동 전파 payload의 simulation mode가 유지된다.

### 전체 검증

```bash
scripts/verify_all.sh
```

운영 Telegram 전송은 자동 테스트에서 실행하지 않는다. 가짜 provider와
훈련 전용 경로를 사용한다.

1. 어느 화면에서 훈련을 시작해도 현장지도·중앙관제·PDF·수동
   전파가 같은 훈련 snapshot을 사용한다.
2. 기존 종합 시나리오 기준 특보 4건, 영향시설 31개소, 상 위험
   10개소가 두 화면과 PDF에서 일치한다.
3. 지도 기상 그래픽이 훈련 특보와 연관되고 실제 관측이 아님이
   모든 관련 UI에 표시된다.
4. 실제 현재 기상은 별도 참고정보로 유지되고 훈련 위험도에 섞이지
   않는다.
5. 훈련 진입·종료로 자동알림 baseline, 실전 중복 방지, 실전 실적이
   변하지 않는다.
6. PC·모바일 실화면에서 모드 배너, 기상 범례, 화면 이동, 실시간
   복귀를 확인한다.
