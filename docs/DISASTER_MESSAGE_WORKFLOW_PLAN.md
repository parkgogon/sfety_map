# 재난문자 분석 이후 업무 흐름 — 설계안

- 작성: 2026-11-08 KST. 기준 소스 `8a21f2c`, `feature/disaster-message-ai`.
- 설계 시작 시 working tree는 깨끗했다. 사용자 요청으로 1·2단계 구현과 로컬 검증까지 진행했다.
- 사용자 요청: 지역 정보 활용 방향을 전제로, 문자 분석 뒤의 구체적인 처리 절차를 정한다.
- 제안 기본값: 중앙관제 관리자가 문자를 선택해 분석하고 지도에서 확인한 뒤 검토 결과를 남긴다.
  자동 수집·분석·발송은 별도 단계다. 기존 KMA 위험도/알림과 이 기능의 상태는 독립한다.

## 1. 설계 시작 시 구현과 연결할 부분

| 항목 | 현재 코드에서 확인한 상태 | 이번 설계 |
| --- | --- | --- |
| 문자 입력/AI 분석 | `/control/messages`, 수동 입력·창작 예문 6종 | 현재 화면을 검토 작업 화면으로 확장 |
| 공식 문자 | 행안부 어댑터가 ID·본문·시각·수신지역을 파싱함 | 관리자용 조회 API/설정/화면 연결을 추가 |
| 문자 수집 범위 | 기존 어댑터는 광역 조회 첫 100행 중 선택 시군의 최근 문자 최대 5건을 반환 | 전체 감시 수집기로 재사용하지 않음. 조회 범위·상한·추가 자료 존재를 표시 |
| 장소·시설 | Kakao 후보와 CSV 거리, 원문 근거·확인 질문 | 후보를 지도에서 확인/수정하고 업무 확인 대상 선택 |
| 지도 기준점 | 지도에 후보 지정→사용자 확인, 주변 거리 계산 구현 | 기존 기능을 공통으로 활용하되 문자와 연결할 저장/복귀 기능 추가 |
| 검토 저장 | 현재 AI 결과는 화면 상태이며 새로고침 후 복구되지 않음 | 전용 검토 기록과 변경 이력 저장 |
| 상황전파 | 기존 모달은 KMA 특보·등급 기반 문구 | 재난문자용 안내 초안/복사를 우선 제공. 실제 발송 연결은 후속 |

행안부 어댑터가 존재한다는 사실은 현재 운영 문자 조회·화면 연결이 된다는 뜻이 아니다.
설계 시작 시 API 설정/서비스/라우트/React에 공식 문자 피드 연결은 없었다. 1단계에서 요청 시 조회 연결을 추가했다.
실제 API 이용 조건·응답·키 설정·조회 완전성은 운영 연결 때 별도로 확인한다.

## 2. 관리자 경험 — 한 건을 처리하는 순서

예시는 창작 문자다: '[달서구] 오늘 10시 대구 성서산업단지 인근 공장에서 화재 발생.
주변 주민은 연기 유입에 주의하고 창문을 닫아 주세요.'

1. **문자 선택 또는 등록**: 원문, 발행 시각, 출처, 수신지역을 확인하고 `AI 분석`을 누른다.
   목록에 보였다는 이유만으로 분석 비용이 발생하지 않는다. 공식 문자는 서버가 조회한
   원본/ID를 사용하며, 붙여넣은 문자는 수동 입력으로 표시한다.
2. **검토 결과 확인**: AI가 상황/시간/사고지/대피지 역할을 나누고 필요한 검색을 수행한다.
   산업단지 대표점 주변 3km의 7개소는 '주변 참고 시설'로 표시한다.
   원문의 공장 위치 미상과 각 판단의 근거를 함께 보여준다.
3. **지도에서 조회 기준점 확인**: 후보와 주변 시설을 한 지도에서 본다. 기준점은 후보를
   사용하거나 직접 수정한다. `이 기준점으로 조회`는 조회 위치 확인이며 실제 사고 지점의
   현장 확인을 의미하지 않는다. 위치 근거 메모도 남길 수 있다.
4. **업무 확인 대상 선택**: 참고 시설은 기본 미선택이다. 관리자가 필요한 시설을 체크한다.
   예를 들어 7개소 중 3개소를 고르는 것은 업무 흐름 설명용 가정이며 실제 검토 실적이 아니다.
   반경 밖 시설이 필요하면 등록 시설 검색으로 추가하고 선정 이유를 남긴다.
5. **검토 결과 저장**: `확인 대상 선정` 또는 `추가 조치 없음`으로 검토를 마친다.
   미해결이면 `추가 확인`에 둔다. 이 선택은 내부 검토 결과이며 재난 종료/안전 판정이 아니다.
6. **안내 초안 활용**: 필요하면 선정 시설·원문·조회 기준·불확실한 사항을 포함한 초안을
   확인/수정/복사한다. 실제 발송과 담당자 확인 여부는 자동으로 기록하지 않는다.

## 3. 화면 구성과 버튼

기존 `/control/messages`를 유지하고 목록과 상세 검토로 확장한다.
PC에서는 목록/상세를 나란히, 모바일에서는 목록→상세로 이동한다. 관리자 인증을 유지한다.

- **목록**: `최근 문자 불러오기`, `문자 직접 등록`, 기간/지역/검토 상태 필터.
  카드에는 출처·수신지역·발행 시각·원문 일부·검토 상태를 표시한다.
  공식 피드 미설정/조회 실패/0건/일부 조회를 구분하고 기존 기록은 유지한다.
- **상세 상단**: 원문과 출처/수신지역, AI 처리 상태, 마지막 분석 시각.
  AI 해석과 관리자 판단을 따로 표시한다.
- **상세 중간**: 상황 구간별 근거/시간/장소 역할·확인 질문, 지도와 장소 후보,
  기준점/조회 거리, 참고 시설과 업무 확인 대상 체크박스.
- **상세 하단**: `추가 확인으로 저장`, `확인 대상 선정`, `추가 조치 없음`,
  `안내 초안 보기·복사`, `변경 이력`.
- 위치 확인 질문은 사람이 다른 기관에 자동 발송하는 질문이 아니다. 관리자가 알아볼
  사항이며, 지역 추가 입력·지도 기준점 수정 등 해당 항목의 조작으로 연결한다.
- 원문 자체는 수정하지 않는다. 관리자 보완 지역·선정 사유·확인 메모는 별도 필드에 남긴다.

## 4. 상태와 변경 규칙

서로 다른 상태를 하나의 '진행 중/완료'로 합치지 않는다.

| 구분 | 값 | 의미 |
| --- | --- | --- |
| AI 처리 | 미분석 / 분석 중 / 분석 완료 / 분석 실패 | 외부 모델 작업의 처리 상태 |
| 관리자 검토 | 미검토 / 추가 확인 / 검토 완료 | 중앙관제의 검토 상태 |
| 완료 시 검토 결과 | 확인 대상 선정 / 추가 조치 없음 | 내부 업무 판단과 이유 |
| 문자 내용 | 발생 / 예방 / 예정 통제 / 통제 유지 / 부분 해제 등 | 원문 구간별 의미. 사건/시설의 실제 현장 상태와 구별 |

- `확인 대상 선정`에는 유효한 시설 ID 1개 이상과 관리자가 확인한 조회 기준/선정 사유를 저장한다.
  `추가 조치 없음`에는 이유가 필요하다. 반경 0개소만으로 안전 판정을 만들지 않는다.
- 지도 기준점/조회 거리가 바뀌면 CSV로 재계산한다. 이 계산 때문에 OpenAI를 다시 호출하지 않는다.
  기존 선택은 변경 이력에 남기고 화면에서 재검토를 요구한다. 초안은 갱신 필요로 표시한다.
- AI 재분석 시 기존 결과를 새 결과로 덮어 지우지 않는다. 분석 버전을 추가하고,
  이전 결과에 근거한 선정/초안은 다시 검토하도록 한다. 실패해도 마지막 결과와 기록을 유지한다.
- 여러 장소/부분 해제는 구간별로 유지한다. 지도에서 검토할 사고/통제 장소를 명시적으로 고르며,
  대피 목적지는 사고 기준점에 자동 대입하지 않는다. 내부 검토 완료가 모든 구간 해제를 뜻하지 않는다.
- 같은 공식 문자 ID 재조회는 중복 등록하지 않는다. 같은 ID의 내용이 달라지면 새 원본 버전과
  재검토 필요를 남긴다. 같은 본문이라도 다른 ID/지역이면 임의로 같은 사건으로 합치지 않는다.
- 두 관리자가 동시에 수정하면 버전 충돌을 알려 다시 읽도록 한다. 공용 관리자 인증으로는
  사람별 신원을 검증할 수 없으므로 변경 시각/세션 범위만 기록하고 실명 감사로 표현하지 않는다.

## 5. AI·규칙·관리자의 역할

| 주체 | 맡는 일 |
| --- | --- |
| 규칙/서버 | 공식 문자 식별·중복/변경 감지, 데이터/인용 검증, 좌표/반경 거리 계산, 상태/저장 조건 |
| AI | 비정형 상황·시점·장소 역할 해석, 필요한 검색 선택, 조회 실패/검증 피드백 후 수정 또는 질문 |
| 관리자 | 미확인 정보 보완, 조회 기준점 확인, 업무 대상 시설 선정, 추가 조치 판단, 안내 문구 검토 |

수신지역은 장소 탐색의 근거로 쓰며 발령기관/사고지와 동일시하지 않는다.
입력에 추가할 지역 메타데이터는 원문 근거와 구분하고 출처를 보존한다.
관리자가 지역을 보완하면 그 사실을 새 분석 입력으로 전달할 수 있다.
모델이 도구 결과를 보고 다음 조회를 바꾸는 현재 연쇄를 유지하며, 단순 반경 변경은 서버 계산으로 끝낸다.
피해 범위·현장 안전·대피소 적합성·거리만으로 점검 우선순위를 모델이 확정하지 않는다.

## 6. 저장과 업무 성과

운영 저장은 기존 Firestore 인프라의 **별도 검토 컬렉션**을 사용하고 KMA 기준 상태/발송 이력을 변경하지 않는다.
로컬/자동 테스트는 메모리 저장소를 주입한다. 운영 저장 실패 시 저장 성공으로 표시하거나 메모리로 조용히 대체하지 않는다.

저장할 최소 정보:

- 원문 ID/버전/내용 해시, 출처 구분(공식·수동·창작), 원문, 수신지역, 발행/조회 시각.
- 분석 버전/모델/실행 시각, 검증된 해석/근거/조회 과정, 해당 분석에 쓴 시설 자료의 해시.
- 구간별 선택한 조회 기준점/원본 후보/좌표 출처/관리자 보완 근거, 조회 반경, 시설 ID와 계산 거리.
- 관리자 검토 상태/결과/이유, 선정 시설 ID, 초안 버전, 변경 시각/레코드 버전.
- 필요한 경우 관련 문자의 연결과 사용자가 입력한 외부 조치 메모. 실제 전송 증거와 구별한다.

담당자 연락처·비밀값·내부 추론 원문·원본 제공자 응답은 저장하지 않는다.
공개 문자 보관 기간/접근 권한/이용 조건은 운영 연결 단계에서 확인한다.
서버가 저장된 분석/CSV로 선정 시설과 거리를 재검증하며 브라우저가 만든 AI 결과를 그대로 신뢰하지 않는다.
현재 분석 응답의 시설 목록은 20개소까지다. 선정용 목록은 서버에서 다시 계산하고 페이지로 나눠 전체를 제공한다.

성과 표시는 문자 검토 건수, 추가 확인 건수, 선정 시설 수와 검토 소요시간부터 시작한다.
창작/수동/공식 입력을 구분하고, 분석 재시도로 건수를 늘리지 않는다.
검토 시간은 등록→검토 완료 시간이며 시스템 화면 밖에서 실제 대응한 시간으로 해석하지 않는다.
문자 여러 건/시설 중복을 구분하고, 원본 시각·지표 정의가 없던 과거 실적은 추정해 채우지 않는다.
피해 예방·현장 확인 완료·담당자 수신/읽음 실적은 이 기록으로 만들지 않는다.

## 7. 구현 단계와 수용 조건

각 단계마다 관련 테스트/화면 검수 후 다음 단계로 넘어간다. 첫 목표는 1~3단계의 업무 한 사이클이다.

### 1단계 — 문자 등록/불러오기와 검토 기록의 기반 (구현·로컬 검증 완료, 미배포)

- 수동/창작 입력 보존, 지역 메타데이터의 구조화, ID/버전 기반 등록과 목록/상세 저장.
- 관리자용 공식 피드 조회 연결. 지역·기간·페이지 상한/일부 조회를 명시하고 요청 시 조회한다.
  현재 최대 5건 필터는 목록 수집 경로와 분리한다. 195개 시설마다 중복 호출하지 않는다.
- API/저장 제공자의 설정 미비는 표시하며, 수동 입력으로 흐름을 검수할 수 있다.
- 수용: 새로고침 후 원문/분석/상태 복구, 같은 공식 ID 중복 방지, 변경 감지, 지역 정보 보존.
- 테스트: 관리자 인증, 재조회/내용 변경/빈 목록/부분 조회/공급자 오류/저장 실패/버전 충돌을 가짜 제공자로 검증.

### 2단계 — 지도에서 기준점 확인과 시설 선정 (구현·로컬 검증 완료, 미배포)

- 후보/수동 기준점을 지도에 표시하고 사고/통제 장소별로 확인한다. 참고 반경은 1/3/5/10km로 통일한다.
- CSV 서버 재계산, 전체 시설 목록 페이지 처리, 기본 미선택, 범위 밖 시설의 사유 있는 수동 추가.
- 원본 분석/관리자 보완을 분리하고 변경 시 선정/초안 갱신을 요구한다. 입력이 바뀐 지점은 원래 인용 근거를 유지한다.
- 수용: 기준점 수정→시설 목록/거리 갱신→선정 저장/복구, 대피 장소 혼입 방지, OpenAI 추가 호출 없이 반경 변경.
- 테스트: 경계 거리, CSV 변경, 0개소/20개소 초과, 여러 장소/부분 해제, 기준점 변경 후 이전 선정, PC/모바일 지도/복귀.

### 3단계 — 검토 결과와 안내 초안

- 세 검토 상태/완료 결과, 이유·선정 시설·변경 이력과 재열기.
- 원문 근거/시점/지역·선정 시설·조회 기준·미확인 사항을 담은 안내 초안과 복사.
  이미 검증된 정보로 서버 템플릿을 구성하며 초안 때문에 별도 유료 AI 호출을 필수로 만들지 않는다.
- 기존 KMA 전파 문구에 이 내용을 끼워 넣지 않는다. 재난문자용 실제 발송 연결은 이후 별도 범위다.
- 수용: 저장/재열기/새로고침, 원문→분석→지도 확인→시설 선정→검토 완료→안내 초안 시연 가능.
- 테스트: 무선정/무사유 완료 방지, 수정에 따른 초안 변경, 창작 표시, 텍스트 복사와 템플릿의 원문/시설 근거.

### 4단계 — 후속 문자 연결과 검토 내역 요약

- 관리자가 같은 상황의 추가/정정/해제 문자를 연결한다. 원본은 각각 보존한다.
- 후속 문자 분석과 구간별 달라진 내용을 표시하고, 이전 검토에 재확인 필요를 남긴다.
- 수용: 일부 해제/다른 장소의 유지 구분, 관련 문자 연결 취소, 기존 선정과 새 근거의 버전 구분.
- 테스트: 동명 타지역/무관 문자 오연결, 부분 해제로 전체 종료하지 않음, 정정 이후 이전 초안 재사용 방지.
- 문자 묶음에 대한 완전 자동 사건 병합은 보류한다. 이 단계의 진행 여부는 앞선 업무 흐름 검토 후 정한다.
