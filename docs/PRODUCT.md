# 제품 정의서

- 문서 상태: 제품 범위 확정, 위험도 정책 초안
- 대상 버전: v3
- 최종 수정: 2026-08-10

## 1. 제품 한 문장

> 소관시설 안전 담당자가 현재 기상특보의 영향을 받는 시설과 점검 우선순위를
> 빠르게 파악하고, 담당자에게 조치를 요청하며 결과를 보고할 수 있도록 돕는
> 기상·재난 관제 도구

이 문장에서 벗어나는 기능은 핵심 화면에 추가하지 않습니다.

## 2. 해결하려는 문제

현재 업무에는 다음 단절이 있습니다.

1. 기상청 특보와 시설 목록이 서로 다른 형태로 관리됩니다.
2. 담당자가 특보 지역에 포함되는 시설을 수작업으로 찾아야 합니다.
3. 어떤 시설부터 확인할지 일관된 기준이 부족합니다.
4. 연락과 보고서 결과가 서로 다른 기준으로 만들어지면 판단이 어긋날 수 있습니다.
5. API 장애와 실제 특보 없음이 같은 화면처럼 보이면 안전 상태를 오인할 수 있습니다.

## 3. 주요 사용자

### 3.1 관제 담당자

- 현재 특보와 영향 시설을 확인합니다.
- 점검 요청을 발송합니다.
- 시설 담당자와 적용 특보를 확인합니다.
- 상황 보고서를 생성합니다.

### 3.2 시설 담당자

- 지도에서 담당 시설과 현재 특보 영향을 빠르게 확인합니다.
- 필요할 때 현재 기상·재난문자·인근 도로 CCTV를 확인합니다.

### 3.3 관리자

- 시설·담당자·위험도 정책을 관리합니다.
- 데이터 수신 오류와 발송 결과를 확인합니다.
- 사용자 권한, 점검 상태, 감사 로그는 v3 범위에 포함하지 않습니다.

## 4. 가장 중요한 업무 시나리오

1. 시스템이 기상청 특보와 특보구역 경계를 조회합니다.
2. 시설 좌표와 특보구역 코드를 기준으로 영향 시설을 계산합니다.
3. 담당자는 최고 특보 단계와 점검 대상 수를 확인합니다.
4. 지도 또는 우선순위 목록에서 시설을 선택합니다.
5. 적용 특보와 담당자를 확인합니다.
6. 필요한 시설에 점검 요청을 발송합니다.
7. 상황 보고서를 생성합니다.

## 5. 제품 원칙

### 5.1 역할별 행동 우선

시설 담당자에게는 단일 시설을 빠르게 찾는 지도를, 중앙관제 담당자에게는
“지금 어떤 시설을 누가 확인해야 하는가”와 일괄 후속 작업을 먼저 보여줍니다.

### 5.2 같은 정보는 한 곳에만

특보 수, 영향 시설 수, 데이터 상태를 여러 카드·배너·패널에서 반복하지 않습니다.

### 5.3 실패를 정상처럼 보이지 않게

정상 0건, 지연 데이터, API 오류, fallback 데이터, 모의훈련을 서로 다른 상태로
표시합니다.

### 5.4 설명 가능한 위험도

모든 등급에는 근거 특보와 적용 규칙이 함께 있어야 합니다. 근거 없는
`AI 기반` 표현은 사용하지 않습니다.

### 5.5 외부 연동과 업무 규칙 분리

KMA 응답이나 Streamlit UI가 변경되어도 지역 매칭과 위험도 규칙은 영향을 받지
않아야 합니다.

## 6. v3 첫 배포 범위 제안

### 포함

- KMA 실시간 특보와 데이터 수신 상태
- 기상청 공식 특보구역 및 내장 fallback 경계
- 시설 데이터 검증과 시설 검색
- 특보구역과 시설의 공간 매칭
- 설명 가능한 위험도와 점검 우선순위
- 통합 지도와 점검 목록의 선택 연동
- 선택 시설의 담당자·적용 특보
- 시설 담당자용 지도 중심 현장 화면과 요청형 현재 기상
- Telegram 시설 딥링크와 등급별 상황전파
- 선택 시설 관할의 공식 재난문자·Google 뉴스 고급 검색 참고정보
- 선택 시설 20km 내 ITS 도로 CCTV 마커·영상 작업창
- 수동 텔레그램 점검 요청
- PDF 상황 보고서
- 명확히 구분된 모의훈련 모드
- 대구·경북·부산·울산·경남의 전체 소관시설

### 첫 배포에서 제외

- 자동 무인 알림 발송
- 예측형 AI 모델
- 홍수·산사태 등 아직 연결되지 않은 데이터 제공자
- 장기 통계·차트
- 시설 정보 자체를 편집하는 관리자 UI
- 불필요한 특보 원본 이미지 표시
- 점검 확인·진행·완료 상태와 과거 이력
- 사용자 인증·권한·감사 로그

## 7. 성공 기준

- 담당자가 화면 진입 후 30초 이내에 최고 위험 시설을 찾을 수 있습니다.
- 데이터 장애가 발생하면 “특보 없음”이 아니라 오류·지연 상태로 표시됩니다.
- 같은 시설과 특보 입력은 UI, 알림, 보고서에서 같은 등급을 냅니다.
- 점검 요청은 대상 시설과 적용 특보를 누락 없이 포함합니다.
- 모바일에서 제목과 필터 때문에 핵심 상황이 첫 화면 아래로 밀리지 않습니다.
- 핵심 업무 규칙은 Streamlit 없이 자동 테스트할 수 있습니다.

## 8. 비목표

- 모든 재난 데이터를 한 번에 통합하는 범용 플랫폼
- 기상청 원문을 그대로 복제하는 화면
- 정교한 예측 모델이 없는 상태에서 위험을 “AI 분석”이라고 표현하는 것
- 지도에 모든 메타데이터를 동시에 표시하는 것

## 9. 확정된 제품 결정

### P-001 제품 범위

- **확정**: 조회, 수동 텔레그램 발송, PDF 보고서까지만 제공합니다.
- 점검 확인·진행·완료 상태와 이력은 저장하지 않습니다.
- 따라서 v3 첫 배포에 업무용 데이터베이스는 도입하지 않습니다.

### P-002 관제 권역

- **확정**: 대구·경북·부산·울산·경남 5개 권역 전체가 관제 범위입니다.
- KMA 코드 prefix `L107`, `L108`, `L114`, `L115`, `L116`을 기준으로 합니다.
- 제품명과 화면 설명에서 대구·경북만을 범위로 오해시키는 문구를 사용하지 않습니다.

### P-003 위험도 정책의 근거

- **확정**: 적용할 공식 내부 기준표는 없습니다.
- 특보 종류와 단계의 조합을 등급으로 직접 연결하는 TOML 정책표를 사용합니다.
- 코드를 수정하지 않고 정책표만 변경할 수 있어야 합니다.
- 여러 특보가 겹치면 가장 높은 등급을 채택하고 모든 특보를 근거로 보존합니다.
- 정책에는 버전, 설명, 등급별 의미와 권장 행동을 포함합니다.
